# 知识模板库：常见问题怎么「入知识库」

> 起因：100 条压测里「发什么快递」必然兜底——它不属于"能力缺失"，属于**知识没录**。
> 但发货、快递、运费、发票、退换这些是全行业都会问的，不该让每个商家从零写。

---

## 一、怎么用（3 步）

1. 客户端 → 工作台 → 知识库 → 「从模板添加常见问题」→ 勾选要的（可一次多选）
2. 点「导入所选」→ 全部以**停用**状态进入知识库
3. 点「编辑」，把正文里的【】改成店铺真实情况 → 保存（保存即启用）

**第 2 步故意不给启用**：模板里【填写快递公司】这种占位如果被直接发出去，就是事故。
不核对就不回答，符合「不编造」。

## 三、多模板怎么选（ask + priority + 冲突检查）

每个模板带两个新字段：

| 字段 | 作用 |
|---|---|
| `ask` | 属于哪类问题（courier / shipping_time / price / invoice…），检索时先按它硬过滤 |
| `priority` | 具体度，1~3；同一类里分数接近时，具体的赢（「能发顺丰吗」>「发什么快递」） |
| `important` | 是否新店必建（6 条） |

导入时还会做**冲突检查**：同一 `ask` 下，两个模板的触发词重叠或互相包含 → 拒绝导入，并告诉你跟哪条打架。

实测：

- 「发什么快递」→ 默认快递公司
- 「能发顺丰吗」→ 能否指定快递（priority 3）
- 「快递不到」→ 未建转寄模板 → 兜底（不瞎猜）
- 「什么时候发货」→ 发货截止时间

## 四、设计约束

| 约束 | 原因 |
|---|---|
| 导入即停用 | 模板里的【】是店铺事实，未经核对就发等于编造 |
| 按标题不覆盖已有条目 | 商家自己写过的，不能被模板冲掉 |
| 关键词给的是**买家口语** | 与知识检索的归一化互补，减少"换个说法就查不到" |
| 回复正文按"可直接发送"写 | 和知识库现有规范一致，不留占位符以外的编辑工作 |

## 四半、开店清单（客户端）

6 条必建模板不再藏在知识库里：

- 标题栏：「开店清单 0/6」，点一下进工作台
- 工作台顶部：黄色提示条「还有 N 条必备模板没建」，按类目列出，可直接点导入
- 全建完后变成绿色「开店清单已完成」

导入仍是停用状态，商家改完【】才启用。

## 四又半、本店高频问题（2026-11-07）

知识库顶部按店铺统计最近 2000 条回复日志，给出该店最常被问的 6 类问题：

```
本店高频问题
 快递公司 344   价格运费 10   发货时间 10   库存 7   议价 4
```

- 数据按 `storeId` 隔离，不跨店；
- 每类问题若还没有对应模板，直接给「补模板」按钮；
- 排除闲聊、隐私、无法归类的提问。

接口：`GET /api/kb/top-asks?storeId=xxx`。

## 五、接口

| 接口 | 作用 |
|---|---|
| `GET /api/kb/templates` | 模板清单 + 是否已导入 |
| `POST /api/kb/import {ids}` | 批量导入，统一 `enabled:false`、`needsConfirm:true` |
| `POST /api/knowledge {item}` | 编辑/启用（沿用现有接口，保存即 `enabled:true`） |

## 六、按日志推荐（已实现）

客户端「工作台 → 知识库」顶部会出现「系统建议」：翻最近日志，只挑 fallback/handoff 的买家原话，
按问题类型归堆，超过 2 次就推荐一条模板，可一键导入。

排除项：测试流量（`test` 标记 / 探针买家 / probe 店铺）、投诉与威胁（那是故意转人工）、闲聊与越界。

接口：`GET /api/kb/suggestions`，返回两部分：

- `items`：日志里反复兜底的问题（≥2 次）
- `missing`：新店还没建的高频模板（快递公司、发货截止、包邮、发票、退换、破损）

客户端「工作台 → 知识库」顶部直接展示这两块，点一下即导入（停用，待核对）。

## 七、还没做
- **类目差异**：当前 32 条是种子/农资口径，食品、化妆品类目需要另一套。
- **版本与来源**：模板要不要带"平台规则版本号"，规则变更时提醒商家复核——待定。
