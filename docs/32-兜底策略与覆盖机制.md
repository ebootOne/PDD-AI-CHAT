# 兜底策略与覆盖机制

> 两个问题：
> 1. 一条条修，总会漏——怎么系统性地少漏？
> 2. 本地没匹配上，该让大模型兜底吗？怎么兜才不像"答错了"？

---

## 一、为什么一条条修永远有漏

因为修的是**句子**，不是**能力**：

- 买家的说法是开放集合（同义、错字、省略、长句多诉求）；
- 用例是人想出来的，覆盖的是"想到的"，不是"存在的"；
- 每修一条，只证明"这一句对了"，不证明"这一类对了"。

### 三个把"漏"变成"可发现"的机制

| 机制 | 做什么 | 解决什么 |
|---|---|---|
| **类型矩阵** | 问题类型（ask）× 回答来源，每个格子定义行为 | 空表一眼看出"哪类问题没人管" |
| **不变量检查** | 对任何回复都成立的硬规则 | 新说法也能被拦住（不依赖用例） |
| **日志挖缺 + 变体生成** | 真实会话聚类缺口；对用例自动生成同义/错字/截断/多诉求变体 | 把"没想到的"变成"测过的" |

**不变量（任何回复都必须满足）**：

1. 不含【占位符】
2. 不含结果承诺（退款/赔付/保证）
3. 不含流程承诺（我帮您查/转人工）
4. 数字必须来自证据（商品字段或知识原文）
5. 商品未知时不说"这款/您买的"
6. 不暴露内部（资料/知识库/模型）

这六条与具体问法无关，所以能兜住"没见过的问题"。

## 二、模型兜底：要，但不是默认通道

### 结论

```
本地有据 → 本地答
本地无据 → 模型（仅限可答类型 + 有证据）
模型也没把握 → 反问 / 体面兜底
```

模型只服务**长尾**，不服务"本该本地答对"的问题。

### 四条准入（缺一不调）

1. **类型准入**：usage / spec / recommend / general 才允许；投诉、退款、索赔、隐私一律不调。
2. **证据准入**：必须带至少一条依据（说明书节 / 商品字段 / 知识条目）。没有依据时，模型只允许"反问或说不知道"，不允许编事实。
3. **成本准入**：一条一问，超时不重试，失败不重试。
4. **模式准入**：自动发送只对白名单类型 + 置信度达标；其余只给候选。

### 三道自检（不过就不采用）

| 检查 | 不过时 |
|---|---|
| 依据：回答里的事实能不能在证据里找到 | 丢弃，走兜底 |
| 对题：问的是哪一类，回答里有没有对应信号 | 丢弃，走兜底 |
| 边界：承诺/立场/内部口径 | 丢弃，走兜底 |

**计费口径：只要产出一条可发送的回复就扣 1 点**，包括被质检丢弃后替换成的兜底回复。

### 兜底文案分三级（这是"不觉得有问题"的关键）

| 级别 | 场景 | 文案形态 | 例 |
|---|---|---|---|
| A 答 | 有据 | 直接答 | 默认发中通哈 |
| B 问 | 缺一个关键信息 | **具体反问一句** | 您说的是站杆还是抽纸？两款不一样 |
| C 兜 | 确实不知道 | 承认 + 给下一步 | 这个我确认后回您，先把您的鹦鹉品种发我 |

**禁止**：
- 「资料里没有」「知识库里没写」（暴露内部）
- 「这个问题我暂时没有准确的信息」（说了等于没说，买家会觉得敷衍）
- 连续两句道歉（态度堆砌，没有信息）

## 三、这次的教训：兜底链路没有健康检查

排查发现服务端 `pdd-cs-backend` 启动即崩（模板里引用了未定义变量），
**模型兜底实际上一直没工作**，但界面和日志都看不出来——所有"模型回答"其实是本地规则。

要补的：

1. 客户端显示「模型通道：可用/不可用」；
2. 每次调用失败记 `backendError`，并在状态栏可见；
3. 启动自检：健康检查不过就降级为"纯本地"，并明确告知。

## 四、落地顺序

| 优先 | 做什么 | 为什么 |
|---|---|---|
| P0 | 本地命中先过"对题"检查（焦点），不过就交模型 | 现在最大问题是**劫持**：问中毒答"都能用" |
| P0 | 兜底文案按 ask 分类，去掉"暂时没有准确信息" | 体面 |
| P1 | 模型通道健康检查 + 状态可见 | 避免"以为在用，其实没跑" |
| P1 | 不变量测试进 CI（六条） | 兜住没见过的问题 |
| P2 | 日志挖缺 + 变体生成 | 持续降漏 |
