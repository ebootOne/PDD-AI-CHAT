# 承诺面与成本纪律

> 两条回复暴露两个问题：
> 1. 「马上安排人跟进」——我们全自动，没有人跟进，这是**假承诺**；
> 2. 「把订单号和照片发我」——我们没有查单能力，也没有看图能力，这句话在**制造下一轮我们答不上来的对话**。
>
> 这属于谈判里的**承诺面控制**：每多一句承诺，就多一项义务、多一个被追问的入口。

---

## 一、承诺面控制（commitment surface control）

谈判里管这个叫 **不做单方面让步 / 不扩大承诺面**（no unilateral concession, no commitment creep）：
你每主动加一句“我帮你查”“我帮你处理”，都是在**单方面增加自己的义务**，而对方不需要付出任何代价。

### 三条硬规则

| 规则 | 含义 | 反例 |
|---|---|---|
| **只陈述，不承诺** | 说事实，不说“我会去做” | “我帮您核实”“马上安排人” |
| **只回应，不引导** | 回答这一问，不抛出新问题 | “把订单号发我”“把照片发我” |
| **能一句说完，不说两句** | 每多一句 = 多一个可被追责的点 | 投诉回了一大段售后流程 |

为什么“不引导”也重要：**我们问什么，买家就会答什么，然后我们就得再答一次**。
而下一轮很可能又是一次“答不上”，于是从一次失误变成连环失误。

### 投诉场景的正确形态

```
亲，非常抱歉给您带来困扰，我们的种子都是从正规渠道进货的。
```

- **一句事实**：正规渠道进货（商家已确认的前提下）
- **一句礼貌**：非常抱歉给您带来困扰
- **到此为止**：不要订单号、不要照片、不承诺检测报告、不承诺退款、不说“安排人”

除非商家在知识库里明确填了「可提供检测报告」，否则**不许说检测报告**——那是又一个我们兑现不了的承诺。

## 二、为什么不能要照片/订单号

| 要照片 | 要订单号 |
|---|---|
| 我们没有识图能力（现在没有） | 我们没有查单/查物流能力 |
| 买家发了，我们必须再回一次，且大概率答错 | 同上，还会把“查不到”暴露出来 |
| 多模态 token 成本是文本的数倍 | 纯文本也要多一次调用 |
| 违反「只回应不引导」 | 违反「不做超出能力的承诺」 |

结论：**全自动模式下，回复里禁止出现“您把订单号/照片发我”“我帮您查一下”“稍等”。**

## 三、图片识别能力：要不要做，怎么收费

### 现状

- 拼多多聊天里的图片是 URL，技术上可以传给多模态模型
- 但：① 图片要出本机（隐私）；② token 成本高；③ 我们的定位是“有依据的回复”，看图判断质量问题本身就需要专业能力

### 三种方案

| 方案 | 做法 | 成本 | 建议 |
|---|---|---|---|
| A. 不做 | 回复里不索取图片；买家主动发图，按文本处理（忽略图） | 0 | **默认** |
| B. 做，单独计费 | 商家开关打开，含图回复按张扣点（如 5 点/张） | 高，需实测 | 二期 |
| C. 商家自带 Key | 图片走商家自己的多模态 Key | 商家承担 | 可选 |

### 计费测算（关键）

- 售价：4000 元 / 600,000 条 ≈ **0.0067 元/条**
- 现有文本模型调用成本按 0.004 元/次估：**一次调用就吃掉 60% 售价**
- 多模态一张图的输入 token 通常是纯文本的数倍，粗估 0.01~0.03 元/张

所以：

1. **图片绝不能不收费地混在文本里**；
2. 含图回复至少按 **3~5 点/条**计，或按实测 token 折算；
3. 上线前必须用真实图跑一次成本，不能拍脑袋。

## 四、成本纪律（商人利益）

### 实测成本（不是拍脑袋）

服务端 `data/usage.jsonl` 里 389 次真实调用：

| 指标 | 值 |
|---|---:|
| 平均 tokens/次 | **584** |
| p50 | 611 |
| p90 | 695 |
| 最大 | 1234 |

按 deepseek-chat 公开价（输入 2 元/百万、输出 8 元/百万，输入/输出约 7:3）折算：

| 场景 | tokens | 单次成本 |
|---|---:|---:|
| 平均 | 584 | **约 0.0022 元** |
| p90 | 695 | 约 0.0026 元 |
| 最坏 | 1234 | 约 0.0047 元 |

所以之前写的 0.004 元/次是**最坏值**，不是均值。

### 毛利测算（售价 0.0067 元/条）

| 模型调用率 | 单条成本 | 毛利 |
|---|---:|---:|
| 20%（本地 80%） | 0.0004 | **93%** |
| 45%（当前水平） | 0.0010 | **85%** |
| 100% | 0.0022 | **67%** |

结论：**现在不亏，但缓冲只有 2~3 倍**。token 翻倍（比如把 12 条历史+4 条知识塞得更满）或模型调用率升到 100%，毛利就掉到 67% 以下；再叠一次重试就接近亏损。

### 五条纪律

1. **本地优先**：能规则/知识库/商品目录答的，绝不调模型；
2. **一次为限**：一条回复最多一次模型调用，禁止重试、禁止多轮内反复调用；
3. **没有依据不调**：本地无知识、无商品的事实类问题，直接兜底（调了也会被判“无依据”）；
4. **图片单独计价**：多模态默认关闭，开启按张扣点；
5. **超时即弃**：服务端超时直接走本地兜底，不重试——重试是双倍成本。

### 平衡（不能只赚钱）

省钱不能省到伤害商家：

- 该给的事实必须给（价格、时效、规则），不能为了省 token 含糊其辞；
- 兜底也要像人话，不能因为免费/便宜就敷衍；
- 成本优化只允许发生在**“本来就不该调模型”**的地方。

## 四半、内外有别：成本只给自己看

| 视图 | 能看什么 | 不能看什么 |
|---|---|---|
| **内部运营**（我们自己） | token、模型调用率、单条成本、毛利、亏损单、供应商价格 | — |
| **商家端（客户端）** | 点数余额 / 消耗、今日回复数、兜底数、待复核、知识缺口建议 | 成本、毛利、模型调用率、供应商报价 |
| **对外话术 / 销售材料** | 「比人工客服便宜一个数量级」这类价值表述 | 「我们每条成本 0.002 元」这类底牌 |

三条纪律：

1. **不主动交底**：商家问“你们成本多少”，回答价值（省了多少人工），不回答成本；
2. **指标换皮**：`本地命中率` 对商家叫「知识命中率」，是质量指标，不是成本指标；
3. **内部视图独立**：运营数据放在我们自己的后台/脚本里，不进商家安装包。

> 谈判原则：信息不对称是定价权的一部分。主动展示毛利，等于把定价权交给对方。

## 五、投诉回复的最终形态（待实现）

```
输入：你们卖假种子 我要投诉
输出：亲，非常抱歉给您带来困扰，我们的种子都是从正规渠道进货的。
```

版本要求：

| 版本 | 回复 |
|---|---|
| 商家已录入「正规渠道」声明 | 上面这句 |
| 商家没录入 | 只保留礼貌：「亲，非常抱歉给您带来困扰，这个问题我记下了。」（不承诺跟进） |
| 商家录入了「可提供检测报告」 | 才允许提检测报告 |

## 六、验收

| 用例 | 必须满足 |
|---|---|
| 你们卖假种子 我要投诉 | 含「正规渠道」（若已录入）；**不出现** 订单号/照片/安排人/稍后/核实 |
| 收到货坏了怎么办 | 只给规则陈述；不要照片、不要订单号 |
| 种子到货了没 | 不索取订单号；只陈述发货/时效规则 |
| 反例：商家开启「有人值守」 | 允许出现「已通知客服」，不能被一刀切 |
