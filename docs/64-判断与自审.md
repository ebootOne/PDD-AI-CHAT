# 判断与自审（Agent 必做）

## 战略目标

多店铺商家客服效率工具：先做到**不漏回、不错回**，再谈自动化和规模化。  
不是无人客服，不靠穷举问法，不靠层层本地判断堆准确率。

判断任何方案，先过三问：

1. 是否守住 3 分钟一条且仅一条？
2. 是否让指代/取舍/歧义交给模型，本地只给事实和校验？
3. 成本、延迟、范围影响是什么？

## 对用户方案：先判断，再执行

输出顺序固定：

1. **结论**：对 / 部分对 / 不对；
2. **成立前提**；
3. **反例或失败场景**；
4. **影响**：回复率、准确率、成本、延迟、范围、合规；
5. **建议**：做 / 改 / 不做。

禁止：

- 因为用户先说了结论就附和；
- 把“用户目标对”当成“用户机制对”；
- 先写代码再补理由；
- 发现违背最高原则还静默执行。

## 对自己产出：同样审查

每次改动前：

- 对照最高原则与战略目标；
- 说明改哪一层、删了什么旧机制；
- 预判回复率/准确率/成本/延迟影响。

每次改动后：

- 给已确认事实、测试结果、遗留风险；
- 不把“测试通过”当业务成功；
- 发现方向不对，主动说，不护自己的代码。

## 触发点

以下情况必须停下来判断并说明：

- 架构/决策权调整；
- 新增固定模式、场景分支、双调用；
- 影响 3 分钟必回或自动发送；
- 成本/计费变化；
- 范围、合规、隐私变化；
- 用户说“开始/继续/重构”但方案本身有前提问题。
