- 主项目：`/Users/helu/Desktop/project/AI CHAT`

## 第一步：读单

```bash
node scripts/issues.js list        # 未处理
node scripts/issues.js stats       # 分布
node scripts/issues.js show ISS-001
```

## 第二步：逐条修（顺序：P0 → P1 → P2 → P3）

每条必须走完这五步，缺一步不算修完：

1. **复现**：照着单里的 `repro` 跑一次，确认能重现；复现不了就回单问，不要瞎改。
2. **归因**：按 `docs/16` 的五步法，写清「还原诉求 → 归类失败 → 缺失思维 → 定义输入/判断/输出」。
3. **改机制，不改话术**：改判断层（understand/judge/router/engine），不许把测试原句塞关键词表，不许为单条加特判。
4. **补回归**：在 `scripts/logic-check.js` 加一条 `check('Kxx', ...)`，或往 `eval/cases.jsonl` 加用例；要能证明"改之前红、改之后绿"。
5. **关单**：

```bash
node scripts/issues.js close ISS-001 --note "改了什么 + 新增的回归用例编号"
```

## 第三步：回归

```bash
node scripts/logic-check.js
node scripts/test-engine.js
node scripts/eval.js
```

三项都通过才向上汇报；有退化就把退化也记成新单。

## 约束

- 一次只修一类问题；PR 式小步，别顺手重构。
- 修不了的单不要关，改写 `--note` 说明卡在哪，留 open。
- 不许为了让单变绿而放宽断言。

## 汇报格式

```md
## 本轮修复
| 单号 | 改的文件 | 回归用例 | 结果 |
|---|---|---|---|

## 未修
| 单号 | 原因 | 需要谁决定 |
```
