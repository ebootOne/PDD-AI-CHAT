# 全自动联调手册（收消息 → 自动发一条）

> 只用于**可控测试会话**。真实买家会话不要开自动。

## 一、前置

1. 桌面端已开，当前店铺已登录；
2. 本地服务 8787、后端 8798 都在；
3. 当前会话最后一条是**买家**，且不是旧消息（首帧只登记，不自动回）；
4. 自动模式开，演练模式关；
5. 只发白名单意图：物流/规格/用法；当前实际能自动的多为物流。

## 二、测试消息

在买家端发这一句（必须和会话里旧消息不同）：

```
什么时候发货呀
```

预期：命中 `logistics` → `auto_send` → 1~3 秒后自动发一条发货时间。

## 三、日志

文件：`data/logs.jsonl`

```bash
node scripts/show-auto-log.js 60
```

一次完整链路应看到：

```
auto_prime        首帧登记，不回复
auto_trigger      检测到新买家消息
auto_result       decision=auto_send / reason=满足自动发送条件
auto_gate         willSend=true / dryRun=false
auto_send_ok      elapsedMs=...
```

失败时看：

| 日志 | 含义 | 排查 |
|---|---|---|
| 没有 auto_trigger | 监控没认为有新消息 | 看最后一条是否买家、消息是否和旧句一样 |
| auto_gate willSend=false | 决策不是 auto_send | 看 auto_result 的 decision/reason |
| auto_fill_fail | 填入失败 | 输入框选择器/页面是否变化 |
| auto_send_fail | 点了发送但输入框没清空 | 平台风控/发送按钮/需要手动回车 |
| auto_error | 生成/接口异常 | 看 error、本地服务 8787、后端 8798 |

## 四、安全闸

- 前端只自动发 `auto_send`，`fallback/suggest` 不发；
- 去重缓存返回 `deduped` 不发；
- 首帧只 `prime`，不把旧消息发出去；
- 服务端要求：意图白名单 + 置信度 ≥0.82 + 营业时段 + 限流。

## 五、停止

关闭「自动模式」即停止；演练模式随时可开，只填不发。

## 2026-11-10 第一次实测

- 买家连发：「什么时候能到呢」「什么时候发货呢」「什么时候发货呀」；
- 「什么时候能到呢」当时走模型，被安全闸留在 `suggest`（模型自动还没开）；
- 「什么时候发货呀」命中本地发货模板，`auto_send`，平台**已发出**；
- 日志误报 `auto_send_fail: 点了发送但输入框没清空`：平台异步清空输入框，600ms 检查太早 → 已改为轮询最多 3 秒；
- 已开模型自动：`autoModel=true`，模型回复过质检 + 物流意图 + 无风险即可自动发。

{"decision":"auto_send","reason":"模型回复通过质检，自动发送","intent":"logistics","autoModel":true}
