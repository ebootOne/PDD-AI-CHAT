# 思维：不替商家否定

> 一句话：**没查到 ≠ 没有**。资质、报告、服务这类问题，宁可给正面口径，也不能替商家说「没有」。

---

## 一、为什么这是思维问题，不是话术

买家问「有质检报告吗」，他真正想确认的是「这东西靠不靠谱、我能不能放心下单」。
回「暂时没有质检报告」，等于替商家把成交的门关上了——哪怕商家其实有报告，只是我们没录。

- 对商家：一句话损失一单，还可能是错误陈述；
- 对买家：得到的是否定信息，不是他要的安心；
- 对我们：把「数据缺失」暴露成「商家缺陷」，违背商人立场。

所以判据不是「这句话好不好听」，而是：**这句话是不是替商家做了一个我们没资格做的否定。**

---

## 二、三档处理

| 情况 | 怎么说 | 例 |
|---|---|---|
| 有证据（知识库/商品页明确写了） | 正面事实，不加戏 | 「有检测报告，下单后可在商品页查看」 |
| 没证据，但问题本身是「有没有」 | **不否定**，给可确认的正面口径 | 「亲，我们都是经过严格筛选的产品哦，具体以商品页标注为准」 |
| 涉及承诺/赔付/时效 | 不承诺结果，给规则或页面口径 | 「按平台售后规则处理」 |

**禁止**：没有 / 不提供 / 不支持 / 无法提供 / 暂无（用于资质、报告、发票、售后能力）。

---

## 三、三条变体 + 一条反例

1. 「有质检报告吗」→「亲，都是经过严格筛选的产品，检测信息以商品页标注为准哈。」✅
2. 「能开专票吗」→「专票需要一般纳税人资料，我这边帮您按流程走。」（有流程才说）✅
3. 「坏了包赔吗」→「按平台售后规则处理，质量问题可以申请售后。」✅
4. 反例：「这款暂时没有质检报告」❌ —— 我们只是没数据，不是商家没有。

---

## 四、落到哪一层

| 层 | 动作 |
|---|---|
| `server/prompt.js` / 后端 SYSTEM | 明确禁止对资质/报告/服务做否定断言；缺数据用正面口径 |
| `server/judge.js` | 检出「没有/不提供 + 质检/报告/证书/资质/发票」→ 换成凭证类正面口径，并记问题 |
| `server/concerns.js` | 凭证类 fallback 已是正面口径，复用 |
| 数据 | 商家补录检测信息后，走「有证据」档 |

---

## 五、这是谁的职责

- **产品经理**：定「哪些话能说、哪些不能说」的对外表达边界（本文第一、二节）；
- **技术负责人**：把边界变成 prompt 约束 + judge 拦截 + 回归用例，保证模型换版本也不跑偏。

只写进 prompt 不够——模型会自由发挥；只写进 judge 也不够——会被改写而不是从源头避免。两边都要有。

---

## 六、这是一种什么思维

不是「写需求时对照四问」，而是一种默认视角：

> **任何一句对外的话，先想它发出去之后买家的反应、商家的损失，再想它对不对。**

拆开是三个自动判断：

1. **这是事实，还是判决？**
   没有证据时说「没有」，不是在陈述事实，是在替商家下判决。
2. **这是我们的状态，还是商家的事实？**
   系统没录到 ≠ 商家没有。把「我们不知道」说成「商家没有」，是角色错位。
3. **买家问的是字面，还是意图？**
   问「有没有报告」，要的是「能不能放心买」；答意图，不答字面。

再加一条底线：**不确定时给出口（页面 / 下一步），不给结论。**

还有一个反向自检：如果一句话让你觉得「我很严谨、我很诚实」，先停一下——
它可能正在替商家关掉一单。诚实不等于和盘托出，不说也不等于撒谎。

这三点不需要背，也不该做成验收清单；它应该在你写每一句客服话、定每一条规则时自动跑一遍。

---

## 七、兜底也要给出口

「不知道」不等于「关掉门」。兜底话术按问法给出口，而不是统一说「我没有准确信息」。

| 场景 | 以前 | 现在 |
|---|---|---|
| 发票 | 这个问题我暂时没有准确信息 | 发票可以在订单页申请，具体以页面显示为准 |
| 规格 | 同上 | 规格以商品页标注为准，点开规格就能看到 |
| 隐私 | 同上 | 这类信息不方便提供，店铺和商品信息以平台页面为准 |
| 通用 | 同上 | 商品和订单的信息以页面标注为准 |

落点：`server/policy.js` 的 `EXIT` / `exitText()`，`pickFallback` 按 `ask` 取出口；
`engine` 与 `index` 在兜底时把 `ask` 传进来。投诉仍先共情，不塞页面口径。
