# 多订单 / 多商品 / 多包裹

## 一、数据

capture 读取右侧所有 `.order-item`，每个订单包含：

```json
{
  "orderNo":"261110-579967424052115",
  "status":"已发货，待签收",
  "items":[{"title":"……","spec":"……","qty":"x1","price":"￥9.90"}],
  "packages":[{"courier":"申通","trackingNo":"773451233139410"}]
}
```

同时保留 `order`（第一单）兼容旧逻辑，新增 `orders[]`。

## 二、本地只筛候选

`order-select.js` 按买家这句话缩小订单候选：

| 买家说 | 订单候选 |
|---|---|
| 大蒜那单发货了吗 | 只含大蒜的订单 |
| 尾号 9410 那单 | 对应订单（尾号重复则多单） |
| 发货了吗 | 全部订单 |
| 两单都有大蒜 | 两单都给模型 |

本地**只做候选筛选，不做最终取舍**。

## 三、模型决策

- 事实块把所有候选订单都带给模型；
- 没点名、多单：模型必须逐单覆盖，或先问是哪一单；
- 点名后：只带该订单事实，模型按该单答；
- 多包裹：逐个报快递+尾号；
- judge 放行多实体澄清问句，并拦截多包裹只报一个。

## 四、真实页面情况

当前真实买家有 3 张订单卡：

- 大蒜：已发货，申通 9410；
- 花椒木站杆：未发货退款；
- 抽纸：未发货退款。

capture 能全部读出；`发货了吗` 带全量事实，`大蒜那单发货了吗` 只带大蒜订单。
