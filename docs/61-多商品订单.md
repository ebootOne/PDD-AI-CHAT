# 多商品订单怎么处理

## 一、已做

capture 现在从订单卡解析商品列表：

```json
"items":[
  {"title":"26年金乡大蒜……","spec":"45mm","qty":"x1","price":"￥9.90"}
]
```

字段来自 `.goods-name / .goods-spec / .goods-num / .goods-price`。

## 二、多商品未点名

买家问「还有吗 / 有货吗 / 多少钱」，订单里有多件，且这句话没点名：

> 亲，您问的是金乡大蒜还是抽纸呀？

- 本地生成，不调模型；
- 只问一句，带「呀」，不承诺动作；
- judge 放行这个澄清问句（`clarify=true`）；
- 算一次回复，满足 3 分钟。

买家点名「大蒜还有吗」→ 走正常商品匹配，不反问。

## 三、当前边界

- 只解析**第一张订单卡**的商品列表；
- 多包裹物流还没做：`courier/trackingNo` 仍是单值；
- 没有真实多商品订单，只用 mock order 验证；
- 商品卡发送 action 还没接。

## 四、验证

- 引擎 37/37（含多商品澄清）
- 事实包 90/90（含澄清放行）
- 真实单商品订单 capture：items 1 条，快递申通、运单 773451233139410

## 多包裹（2026-11-10 补）

订单卡现在解析：

```json
"packages":[
  {"courier":"申通","trackingNo":"773451233139410"},
  {"courier":"中通","trackingNo":"753123456789"}
]
```

- capture 会依次点开每个「物流信息」，把所有快递/运单读出来；
- 兼容旧字段：`courier/trackingNo` 取第一个包裹；
- 多包裹时 facts 写「包裹：申通尾号9410；中通尾号6789」，不再写单一快递；
- judge 发现候选只报一个包裹，会改成逐个报；
- 实测单包裹 capture 正常；多包裹用 mock order + 解析夹具验证。

仍未做：真实多商品/多包裹订单的页面验证；商品卡 action。
