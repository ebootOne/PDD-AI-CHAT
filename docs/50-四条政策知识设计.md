# 四条政策知识：标题 / 关键字 / 回复设计

> 这四条不是“给机器看的规则”，是**给商家看的示例**：标题一眼懂、关键字覆盖常见说法、回复像正常商家说的话。
> 同时它们要能被四个模板命中，带条件的问法要交给模型。

---

## 一、设计原则

1. **标题 = 意图名**：商家扫一眼知道这条管什么；
2. **关键字 = 常见说法**，不写条件词（地区、顺丰、专票、发货了吗）；
3. **回复 = 结论 → 条件 → 出口**：先说结果，再补边界，最后给“以页面/实际为准”；
4. 一条只答一个意图，不塞第二个问题；
5. 不写“保证/一定/绝对”，不编检测数据。

---

## 二、四条示例

### 1. 发货时间

- 标题：`发货时间`
- 关键字：什么时候发货、多久发货、几天发货、什么时候能发、什么时候发出、发货时间、几点前发货、当天能发吗、今天能发吗、发货要多久、啥时候发货
- 回复：

> 亲，当天16点前付款的订单当天发出哈，16点后的顺延到第二天。节假日和活动期间可能慢半天，发货后单号会同步到订单里。

**为什么不放「发货了吗」**：那是状态题，需要订单事实，不能拿发货时间硬答。

### 2. 快递公司

- 标题：`快递公司`
- 关键字：发什么快递、什么快递、哪家快递、用什么快递、默认发什么快递、快递公司、发哪个快递、什么物流
- 回复：

> 亲，咱们默认发中通哈，偏远地区发邮政。需要指定快递的话可以备注，能不能发以实际发货为准哦。

**为什么不放「顺丰」**：指定快递是条件题，守卫会拦下来交模型。

### 3. 包邮与运费

- 标题：`包邮与运费`
- 关键字：包邮吗、包邮不、包邮、全国包邮吗、运费多少、邮费多少、要运费吗、免运费吗、运费怎么算
- 回复：

> 亲，除新疆、西藏、内蒙古外都是包邮的哈；偏远地区下单时页面会显示补差运费，按页面显示来就好。

**为什么不放「新疆/内蒙古」**：一带地区就是条件题，模板守卫会拦，交模型按地址答。

### 4. 发票

- 标题：`发票`
- 关键字：能开发票吗、开发票、有发票吗、能开票吗、开票、要发票、发票怎么开、电子发票、普票
- 回复：

> 亲，可以开电子普票哈，下单后在订单里填好抬头和税号，当天开出后会发到订单邮箱。专票需要一般纳税人资料，走对公流程，您需要的话跟我说。

**为什么不放「专票/抬头」**：专票是条件题，守卫会拦；回复里保留一句说明，模型答时也能用。

---

## 三、命中链路

1. 四个模板规则（`server/templates.js`）判断“是不是这四类问法”；
2. 命中后按 `ask` 找当前店铺知识条目（标题 + 关键字）；
3. 带条件的问法被守卫拦下 → 交模型（带事实/知识）；
4. 条目设了 `noShort`：回复不截短，条件句不会被“简短候选”吃掉。

---

## 四、验收

| 问句 | 期望 |
|---|---|
| 什么时候发货 / 发什么快递 / 包邮吗 / 能开发票吗 | 本地四条示例 |
| 发货了吗 / 内蒙古包邮吗 / 公司抬头能开票吗 / 能发顺丰吗 | 模型 |
| 回复必须包含条件句（节假日/指定快递/偏远补差/专票） | 本地完整回复 |
