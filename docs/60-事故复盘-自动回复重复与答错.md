# 事故复盘：自动回复重复 + 答非所问（2026-11-10）

## 一、现象

真实店铺会话中，买家连续收到：

- 两条完全相同的「亲，收到您的消息了，我帮您看看具体情况哈。」；
- 一条「亲，您发的这串数字我这边看不到物流详情呢。」——买家没有发数字；
- 随后拼多多出现 **「纠纷预警，请立即跟进」**。

## 二、时间线

| 时间 | 事件 |
|---|---|
| 18:48 | 买家发「什么时候发货呀」，自动生成成功，但发送用 JS click，平台不认 |
| 18:50 | 商家手动点击发出第一条回复 |
| 18:57 | 买家发「大概什么时候能到」，自动判兜底但未发 |
| 19:00 | 测试 trusted click / Enter，补发两条相同兜底 |
| 19:02 | 模型回复「您发的这串数字…」被自动发出；下一条候选被质检改写，重复兜底被平台拦截 |
| 19:02 | 手动补发正确到货口径，停止倒计时 |
| 19:03 | 出现纠纷预警 |

## 三、根因

1. **发送通道错**：JS `click()` 不是可信事件，拼多多不发送；输入也必须主进程 `insertText`。
2. **重复兜底**：同一条消息连续发相同文本，被平台判重复/敷衍。
3. **无依据内容**：模型说“您发的这串数字”，买家没发；judge 没拦住。
4. **真实店铺做联调**：应该在演示店/测试买家号先跑，真实店只做只读验证。

## 四、已修

- 主进程可信 Enter 发送，实测 400ms 成功；
- 自动发送前同文案 2 分钟去重；
- judge 增加「不能说买家没发过的数字/单号」；
- 3 分钟规则细化为：**一条且仅一条**，不重复轰炸；
- 自动发送已关闭，真实店铺不再自动发。

## 五、后续红线

1. 自动发送只允许在**演示店/测试买家号**验证；
2. 真实店铺重新开启前，必须通过：
   - 同一消息只发一条；
   - 重复文案拦截；
   - 无依据内容拦截；
   - 发送失败不重试成轰炸；
3. 3 分钟回复率不能以重复/答错为代价；宁可一条安全兜底，不发第二条。
