# 最高原则统计（三条）

> 所有规则、架构、代码、测试都以这三条为判断基础；冲突时按顺序优先。

## 最高原则

| 编号 | 原则 | 含义 | 判断标准 |
|---|---|---|---|
| **P0-1** | **回复率** | 3 分钟内必须发出**一条且仅一条**回复 | 超时=事故；重复=事故；任何理由不能导致不回复 |
| **P0-2** | **必回下准确率** | 必回前提下，内容必须有依据、不编造、不答错 | 不确定发安全兜底；不为准确率不发/重复发 |
| **P0-3** | **商家立场，真实解决** | 每条回复服务商家经营目标，并真实解决买家当前需求 | 不以发出/答完/模板命中为完成；不用话术或流程替代解决 |

## 一句话总结 P0-3

**站商家经营立场，用智能回复真实解决买家当前问题，而不是完成一次回复动作。**

## 支撑原则（服务三条最高原则，不得反向压制）

| 编号 | 原则 | 说明 |
|---|---|---|
| S-1 | 决策分工 | 指代、取舍、歧义、上下文由模型决策；本地只供事实、校验、执行 |
| S-2 | 成本护栏 | 成本是约束不是决策者；不写死固定调用次数；不为省成本牺牲回复率/准确率 |
| S-3 | 安全边界 | 不编造、不泄露隐私、不越权承诺、不替商家否定；商用过资质门禁 |

## 战略目标

多店铺商家客服效率工具：先不漏回、不错回，再自动化和规模化；不靠穷举问法、固定模式、层层判断。

## 三条之间的关系

```
P0-1 回复率（硬红线）
  └─ P0-2 必回下准确率
       └─ P0-3 商家立场，真实解决
            ├─ S-1 模型决策上下文
            ├─ S-2 成本护栏
            └─ S-3 安全边界
```

- P0-1 优先于 P0-2：不能为了准确而不回、晚回、重复回。
- P0-2 优先于 P0-3：不能为了“真实解决”编造、越权承诺。
- P0-3 是方向：只做到“回了、答了”不算完成，必须对商家经营和买家问题都有真实价值。

## 当前实现差距

| 原则 | 当前状态 | 主要冲突 |
|---|---|---|
| P0-1 | 有 3 分钟 watchdog；固定规则/固定双调可能延迟 | 规则 2“直接转人工”、固定双调、自动白名单 |
| P0-2 | 黄金集通过，但模型波动和上下文答错仍存在 | 本地固定分支、judge 场景 guard |
| P0-3 | 未度量；存在“看页面”“答了但没解决” | 无解决率指标；页面口径当解决 |
| S-1 | 候选池/used/need 已有；仍有 `contextFirst=有订单`、固定两段 | 本地按上下文类型决策 |
| S-2 | 规则已改为原则；代码仍固定双调 | 订单上下文固定两次 |
| S-3 | 有 judge/敏感词/隐私过滤 | 凭证题、承诺题波动 |
