# 最高原则统计（对话归并）

统计方法：把对话里反复出现的表述按语义合并，不按词频；区分用户明确说过的、以及从战略目标推导的。

## 一、原则清单

| 编号 | 原则 | 依据 | 层级 |
|---|---|---|---|
| P0-1 | 3 分钟内必须发出**一条且仅一条**回复；不回复会被平台罚款 | 用户原话：“回复率是优先级最高，不能出现不回复……三分钟没有回复，商家会被罚款” | 最高红线 |
| P0-2 | 必回前提下准确率优先；宁可安全兜底/答错，不能超时；不重复、不编造 | 用户原话：“以准确率为核心”；事故复盘：重复回复、编造买家内容 | 最高红线内的第二优先 |
| P1-1 | 指代、取舍、歧义、上下文判断由模型决策；本地只供候选事实、校验、执行 | 用户多次纠正：“不要有本地权重”“本地只是手段” | 架构原则 |
| P1-2 | 智能回复不能靠穷举问法、固定模式、层层判断、补丁叠加 | 用户原话：“靠穷举或者靠叠加层层判断肯定是写不好的” | 架构原则 |
| P2-1 | 成本是护栏，不是决策者；不得为省成本牺牲回复率/准确率 | 用户原话：“成本最后”；AGENTS 最高原则 4 | 约束 |
| G-1 | 面向多店铺商家的客服效率工具：先不漏回、不错回，再自动化和规模化 | 产品定位 + 用户战略表述 | 战略目标 |
| S-1 | 不编造、不泄露隐私、不越权承诺、不替商家否定；商用过资质门禁 | 事故复盘 + AGENTS 硬规则 | 安全边界 |

## 二、层级关系

```
P0-1 回复率/3分钟一条
  └─ P0-2 准确率（在不超时、不重复的前提下）
       └─ P1-1 模型决策上下文
       └─ P1-2 不做穷举/固定模式
            └─ P2-1 成本护栏
G-1 战略目标：以上原则服务的目标
S-1 安全边界：任何时候不得突破
```

## 三、当前实现差距

| 原则 | 当前状态 | 主要冲突 |
|---|---|---|
| P0-1 | 有 3 分钟 watchdog；但固定规则/双调可能延迟或阻断 | 规则 2“直接转人工”、规则 3 自动白名单、固定双调 |
| P0-2 | 单测/黄金集通过，但有模型波动与场景答错 | 本地固定分支、judge 场景 guard、上下文错误 |
| P1-1 | 候选池/used/need 已有；但 `contextFirst=有订单`、固定 `select→answer` 仍是本地决策 | contextFirst、两段式固定、entitySensitive |
| P1-2 | 未达成 | 规则 7/20 固定 3+1、规则 9 固定步骤、代码多处分场景判断 |
| P2-1 | 规则已改为原则；代码仍固定双调 | 订单上下文固定两次调用 |
| G-1 | 单店验证为主，多店铺未验证 | 范围/资质未定 |
| S-1 | 有 judge/敏感词/隐私过滤；仍有模型波动 | 凭证题、承诺题 |

## 四、统计结论

- 真正的最高红线只有两条：**P0-1 回复率/一条**、**P0-2 必回下准确率**。
- P1-1/P1-2 是保证 P0-2 的架构原则，不是可选项。
- P2-1 是约束，不能反过来压 P0。
- G-1 是目标，S-1 是边界。
- 当前代码对 P0-1、P1-1、P1-2、P2-1 都有未合规点；先改直接影响 P0 的固定规则，再改架构固定分支。
