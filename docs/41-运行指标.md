# 运行指标（内部）

> 只看我们自己：本地命中率、模型调用率、兜底率、事实包健康度。
> 模型调用率与成本**不对商家展示**（AGENTS 第 12 条），所以不放进工作台的商家页。

---

## 一、怎么取

```bash
node scripts/metrics.js            # 近 1 天，排除测试会话
node scripts/metrics.js 7          # 近 7 天
node scripts/metrics.js 7 --test   # 包含 test:true 的会话
```

底层接口（只监听 127.0.0.1）：

```
GET /api/metrics?days=1&includeTest=0
```

返回里带 `internal: true`，表示不能直接给商家看。

## 二、指标定义

| 指标 | 定义 |
|---|---|
| 本地率 | 非模型、非转人工的回复 / 总回复 |
| 模型调用率 | `source=backend` / 总回复 |
| 兜底率 | `decision=fallback` / 总回复 |
| 平均扣点 | 总扣点 / 总回复 |
| 均延迟 | 请求总耗时（含模型调用）均值 |
| 事实包平均 tokens | 只按有 `factTokens` 的包算 |
| 事实包平均条数 | 只按有 `factItems` 的包算 |
| 扩召回率 | `factMode=wide` / Pro 事实包数 |
| 空包率 | `factMode=empty` / Pro 事实包数 |
| 注册表命中率 | `factRegistry` 非空 / 有该字段的包（旧日志没有字段，不计入分母） |
| 引用非法 | `factInvalid` 总和（必须为 0） |
| 未处理缺口 | `route-gaps.json` 里 status=open 的条数 |

## 三、实测样例（2026-11-09，含测试会话）

```
引擎      回复   本地率   模型率   兜底率   平均点   均延迟
standard     2    100%      0%      0%     0.5      3ms
pro         12   66.7%   33.3%      0%   0.599    402ms
unknown   2870   92.4%    7.4%   14.1%   0.769      1ms

事实包：335 个 · 平均 70 tokens / 1.3 条
  正常 288 · 扩召回 47（14%）· 空包 0（0%）
  注册表命中 6（85.7%）· 带缺失 6（1.8%）· 引用非法 0

注册表未处理缺口：10 条
```

- `unknown` 是加 `engine` 字段之前的历史日志，会随时间自然淘汰；
- Pro 均延迟 402ms，是把模型那次算进去的；普通版 3ms 说明本地路径没退化；
- 引用非法 0，说明 `used` 校验在拦住假引用。

## 四、该盯什么

| 指标 | 异常信号 | 先查哪里 |
|---|---|---|
| Pro 本地率骤降 | 可能路由/注册表把简单问题也推给模型 | `route-gaps` + 注册表误匹配 |
| 扩召回率持续升高 | 路由覆盖不足，或事实块取数退化 | `/api/facts/preview` 看 trigger |
| 空包率 > 5% | 知识/商品数据缺失 | `gaps.json`、商品同步时间 |
| 注册表命中率过高（>50%） | 静态表可能太弱，该把短语固化进 `ASK_BLOCK` | `fact-route.js` |
| 引用非法 > 0 | 模型在编事实编号 | 后端 prompt / `used` 校验 |

## 五、边界

- 只读最近 5000 条日志，跨度大了要分批；
- 测试会话默认排除，看效果用 `--test`；
- 成本/毛利不在这里算（成本只在服务端 `usage.jsonl`，本文件不导出）。
