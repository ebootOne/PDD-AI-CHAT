# 讨论纪要：真正的可行性、平台规则、以及我们需要什么样的人

> 参与：产品经理 + 技术负责人
> 日期：2026-11-05
> 前提：工具产品，Windows + Mac；使用者登录**真实**拼多多商家后台；多店铺；自动识别真实咨询并给出准确、合规的回答。

---

## 一、先说三个会决定产品生死的事实

### 1. 平台考核的是「3 分钟人工回复率」，而且**机器人不算**

- 口径：`3分钟人工回复率 = (咨询人数 − 3分钟未人工回复累计) / 咨询人数`，考核时段 **08:00–23:00**。
- **自动回复、欢迎语、商品卡片弹窗不计入**；必须是「人工账号发出的消息」才算有效应答。
- 回复率低于阈值会分档影响：搜索权重、活动报名、领航员评分。公开说法 90% 以上算安全，70% 以下明显降权（**具体阈值以后台口径为准，待核实**）。

来源：[萌萌客·拼多多客服回复规则](https://www.mmker.cn/article/3874.html)、[聊天宝·回复率与降权](https://www.bangkefu.com/article/pinduoduo-kefu-huifulv-tisheng.html)（均为第三方整理，非平台原文 🟡）

**这条事实把产品劈成了两半：**

| 我们做的事 | 对考核有没有用 | 风险 |
|---|---|---|
| AI 生成候选，人点发送 | ✅ 算人工回复 | 低 |
| AI 生成候选，工具代替人点发送 | ⚠️ 平台看到的是"人工账号发的"，大概率计入 | **中高**：可能被判自动化 |
| 用平台自带机器人/自动回复 | ❌ 不计入 | 无 |

**所以"自动发送"不是一个体验开关，是一个业务赌注**：赌平台把"工具代点发送"视为人工回复。这一点必须实测（发一条，隔天看后台回复率有没有算进去），不能靠猜。

### 2. 多店铺 = 多账号登录态，这是最大的架构分叉

一个人守 8 个店，意味着 8 套登录态。三种做法，风控与成本完全不同：

| 做法 | 体验 | 风控风险 | 工程成本 |
|---|---|---|---|
| A. 同一浏览器多标签，各自登录 | 差（切号要重登） | 低 | 低 |
| B. 每个店一个浏览器 Profile（多开） | 好 | **中**：同设备多账号易触发验证 | 中 |
| C. 桌面客户端内嵌多浏览器实例 | 最好 | 中高 | 高（Win/Mac 双端打包、签名、更新） |
| D. 官方开放平台授权 | 最好 | 低 | 需要企业资质 + 权限未知 |

> 2026-11-06 定案：直接走 C（桌面客户端），A（扩展）弃用。以下是当时的判断记录。

**技术负责人的判断**：v1 走 A（扩展天然支持多标签），v2 再做 B；C 只有在"多店托管/无人值守"成为刚需时才做。**不建议做 D 之外的任何"服务端代登录"**——代持商家账号密码，出事是刑事级别。

### 3. 「准确回答」不是模型问题，是知识供给问题

客服问题 80% 是重复的：发货时间、规格、优惠、退换、快递、补偿。模型再强，不知道你店里"16 点前当天发"就是答不对。

所以真正的工程是：**商品说明书 + 售后政策 + 订单上下文 → 结构化知识 → 检索 → 有依据的回答 → 没依据就转人工**。这条链已经在 v0.1 里跑通了。

## 二、Windows + Mac：可行性结论

| 形态 | Windows | macOS | 多店 | 改版抗性 | 结论 |
|---|---|---|---|---|---|
| Chrome/Edge 扩展 + 本地服务 | ✅ | ✅ | 多标签 | 中 | **v1 首选**，一套代码两端跑 |
| Electron 壳（内嵌浏览器） | ✅ 需签名 | ✅ 需公证 | 多实例 | 中 | v2，多店托管时再上 |
| 纯 Web SaaS | ✅ | ✅ | 强 | 低（拿不到登录态） | 不可行（跨域） |
| 官方 API | ✅ | ✅ | 强 | 高 | 取决于权限 |

**跨平台的真实成本在"分发"不在"代码"**：
- Windows：代码签名证书（OV/EV，几千到上万/年），否则 SmartScreen 拦截；
- macOS：Apple Developer 账号（$99/年）+ 公证（notarization），否则 Gatekeeper 拦截；
- 更新：需要自建更新源或用电子的 autoUpdater；扩展则走商店或企业策略分发。

扩展方案在这三件事上成本最低：**不用签名、不用公证、更新即刷新**。这是它作为 v1 的核心理由。

## 三、产品经理要整理的「客服回复规则」（初版，待平台原文核对）

> 标注：✅ 平台明文/行业公认 ｜ 🟡 第三方整理待核 ｜ 🔵 我们的产品策略

### A. 时效类

| 规则 | 内容 | 产品动作 |
|---|---|---|
| 3 分钟人工回复率 | 08:00–23:00 考核；机器人不计入 🟡 | 面板显示"距 3 分钟还剩 X 秒"倒计时；超时前 30 秒变红 |
| 首答要快 | 先接住再找答案，比答得完美更重要 🔵 | 一键"承接语"（在的呢，您说的是哪款？） |
| 平均回复时长 | 参考 45 秒以内 🟡 | 统计并展示 |
| 最长无回复间隔 | 参考 5 分钟以内 🟡 | 待办提醒 |

### B. 用语类（红线，命中即拦截）

| 类别 | 禁止内容 | 处理 |
|---|---|---|
| 第三方平台 | QQ、微信、淘宝、京东、手机号、二维码、链接（含缩写、谐音） ✅ | 生成侧拦截 + 提示改写 |
| 称呼 | 把商品叫"宝贝"（平台要求说"商品/产品"） 🟡 | 词表替换 |
| 极限词 | 最、绝对、全网、唯一、第一、顶级、100% ✅ | 词表拦截 |
| 辱骂/人身攻击 | 任何侮辱、诽谤、恐吓、引起不满的字句 ✅ | 拦截 + 记入复核 |
| 诱导好评 | 好评返现、给好评才发货 ✅ | 拦截 |
| 隐私 | 发送买家完整手机号/地址 ✅ | 打码 |

### C. 行为类

| 规则 | 内容 | 产品动作 |
|---|---|---|
| 不得骚扰 | 不得频繁联系、短信/电话轰炸 ✅ | 限流：同会话 8 秒 1 条、全局 20 条/分钟 |
| 不得虚假承诺 | 不承诺赔付金额、到货时效、功效 🟡 | 知识库没有就不生成 |
| 售后必须走平台流程 | 不引导私下转账/到付 ✅ | 拦截"转账/到付/线下" |

### D. 我们的产品策略（非平台规则）

1. **默认建议模式**：AI 只填输入框，发送键由人按——既保住"人工回复"口径，又不赌风控。
2. **风险会话强制转人工**：投诉、索赔、平台介入、要求站外联系。
3. **每条回答带依据**：知识库没有的，不给候选。
4. **自动发送是"进阶开关"**，默认关，且必须先在自家店实测回复率口径。

## 四、这个产品需要什么样的产品经理

**不要通用的 SaaS PM。** 这个产品的 PM 必须同时具备三样东西：

1. **一线客服的体感**
   坐过班、被 3 分钟倒计时追过、知道 19:00–22:00 是什么样子。否则设计出来的流程一定是"看起来很智能，用起来多三步"。

2. **把平台规则翻译成产品规则的能力**
   平台写的是"不得使用侮辱性用语"，产品要能落成：词表 → 生成侧拦截 → 输出侧二次检测 → 复核队列 → 审计日志。这是**规则工程**，不是写 PRD。

3. **克制**
   这个品类最容易犯的错是"加功能"：加多店聚合、加数据看板、加客户画像、加企微导流。每加一个，商家就多学一步、多一个出错点。
   **判断标准**：新增功能必须删/并/延一个；主任务永远 ≤ 3 步。

**加分项**：懂种子/农资这类"知识密集型类目"（你截图里的店都是种子店），因为这类目最吃知识库，最能体现价值。

**不合格信号**：一上来就谈"全自动无人客服""多平台打通""AI 数字员工"。

## 五、这个产品需要什么样的技术负责人

**不要只会写 CRUD 的后端。** 需要四种硬能力：

1. **浏览器自动化 / DOM 逆向**
   页面天天改，选择器随时失效。核心能力不是"写一次能跑"，是**快速恢复**：诊断工具、结构快照、选择器热更新、失败自动降级。v0.1 里那个「诊断」按钮就是这个能力的雏形。

2. **多账号与风控的边界感**
   知道什么能做、什么不能碰：不代持密码、不伪造设备指纹、不绕过验证码、不做服务端群控。**能对老板说"这个不做"**。

3. **跨平台交付**
   Windows 签名 + macOS 公证 + 自动更新 + 崩溃上报。这是"能卖"和"能跑"的区别。

4. **LLM 工程，而不是调 API**
   结构化输出契约、检索质量、评测集、幻觉拦截、成本控制。要能回答"这条回答为什么可信"，而不是"我们接了 GPT"。

**加分项**：做过 RPA / 电商 ERP / 浏览器插件；懂个保法与生成式 AI 备案的基本要求。

**不合格信号**：上来就说"用 Cookie 池 + 协议逆向，稳定得很"。

## 六、现在必须一起拍板的五件事

1. **多店铺怎么登录？** A 多标签 / B 多 Profile / C 桌面多实例 / D 官方授权。
2. **自动发送做到哪一档？** 只建议 / 建议 + 一键发送 / 白名单自动 / 全自动。
3. **先验证哪件事？** 我的建议：先用真实店发一条工具生成的回复，隔天看后台「3 分钟人工回复率」有没有算进去——**这一条决定自动发送能不能做成卖点**。
4. **卖给谁？** 自家店群 / 同行商家 / 服务市场。
5. **类目先做哪个？** 种子农资（知识密集，价值高）还是通用（好复制）。
