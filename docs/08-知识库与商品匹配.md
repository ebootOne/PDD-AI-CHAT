# 知识库来源 + 商品匹配机制（PM 调研 / 技术负责人落地）

> 日期：2026-11-05
> 结论先行：知识库必须归商家；商品匹配不是"AI 猜"，是"查三张表"；链接不能裸发。

---

## 一、知识库该由谁写：三源并存，但都要过人的手

### 1.1 三种来源

| 来源 | 谁生产 | 典型内容 | 占比预估 |
|---|---|---|---|
| **A 商家自己上传** | 商家 | 售后政策、发货时间、客服话术 | 60% |
| **B 商品数据自动生成** | 工具生成草稿 + 商家确认 | 规格、品种、用法、适宜区域 | 30% |
| **C 对话里沉淀** | 工具发现 + 商家确认 | "这个说法我们店其实这么回" | 10%，但增速最快 |

我们提供的**不是模板，是模板的起点**。现在的 13 条种子知识只是"示例"，必须能删、能改、能全清空。

### 1.2 一条铁律：AI 只生成草稿，不自动入库

```
AI 生成草稿 → 待确认队列 → 商家点「启用」→ 生效
```

理由很直接：知识库写错一句，赔的是商家的钱。自动入库等于把责任推给算法，商用产品担不起。

### 1.3 导入形式（按优先级）

1. **Excel / CSV 批量导入**（最实用，商家的运营表格现成）
   ```
   标题, 关键词, 回复内容, 适用商品ID, 状态
   发货时间, 什么时候发货|几天发货, 当天16点前付款当天发出…, , 启用
   白萝卜播种, 白萝卜怎么种|播种期, 春播3月中下旬…, 1001, 启用
   ```
2. **逐条表单**（已实现，在「工作台 → 知识库」）
3. **从商品链接生成草稿**（输入商品链接 → 抓标题/规格 → 生成 3~5 条知识草稿 → 商家确认）

### 1.4 每条知识必须带「来源」标记

`手动 / AI生成 / 对话沉淀 / 导入` —— 出问题时能追到是哪来的，也方便按来源统计准确率。

## 二、商品匹配：不是 AI 理解，是查三张表

你说"这个匹配机制我不太懂"——我用大白话讲一遍。

### 2.1 先看一个真实例子

买家说：**「你们有萝卜吗？」**

系统做四步：

```
第 1 步  把话归一化
        "你们有萝卜吗" → "你们有萝卜吗"

第 2 步  拿商品表的「品类词 + 别名」去话里找
        商品表里有：
          白萝卜   品类=白萝卜   别名=[萝卜, 白萝卜, 大白萝卜]
          樱桃萝卜 品类=樱桃萝卜 别名=[萝卜, 樱桃萝卜, 小萝卜]
          胡萝卜   品类=胡萝卜   别名=[胡萝卜, 红萝卜]
        "萝卜" 命中了前两个 → 胡萝卜不命中（它叫胡萝卜，不叫萝卜）

第 3 步  看库存，有货的排前面

第 4 步  套模板出话
        "有货的，这几款都有：白萝卜、樱桃萝卜。您要哪一种？我把链接发您。"
```

**全程没有 AI 参与，就是查表。** 所以它快（0ms）、便宜（0 元）、可解释（能说出命中了哪个词）。

### 2.2 为什么不用向量/大模型做这件事

| | 查表（当前） | 向量检索 | 大模型 |
|---|---|---|---|
| 准确率 | 高（别名可控） | 中（商品标题是关键词堆的，向量反而糊） | 中（会编价格/库存） |
| 可解释 | 能说出命中哪个词 | 说不清 | 说不清 |
| 成本 | 0 | 有 embedding 费用 | 每条几分钱 |
| 出错怎么修 | 加个别名，1 分钟 | 调阈值，靠猜 | 改 prompt，不一定灵 |

商品标题长这样：`意大利生菜种子籽四季播耐寒蔬菜种籽`——它是关键词堆出来的，语义很"脏"。这种情况下查表比向量稳。

### 2.3 什么时候才需要 AI

当买家问的是**属性**而不是**品名**：

- "有没有能生吃的、长得快的、阳台能种的？"
- "哪个适合北方现在种？"

这已经超出"找具体商品"，属于"按条件推荐"。这层放到 v2：给商品打结构化标签（可生食/生长周期/适宜区域/耐寒等级），再做条件匹配。

### 2.4 置信度怎么定，什么情况转人工

| 情况 | 置信度 | 动作 |
|---|---|---|
| 精确命中品类词 + 有货 | ≥ 0.85 | 直接给候选 |
| 只命中标题片段 | ~0.55 | 给候选但强制人工确认 |
| 命中多个品牌/规格，无法区分 | — | 列出来让买家选，不替他决定 |
| 完全没命中 | 0 | 转人工，不编"我们有的" |

## 三、发链接这件事，拼多多和淘宝不一样（坑在这）

你想要"像淘宝那样给一个真实商品链接"，但拼多多的现实是：

| 方式 | 可行性 | 风险 |
|---|---|---|
| 聊天里发裸 URL | 技术上能发 | **高**：平台违禁词明确禁止发链接，可能判站外导流 |
| 发「商品卡片」 | 正规做法 | 低 |
| 让买家自己去搜 | 体验差 | 无 |

拼多多商家后台聊天框工具栏有「商品」按钮，点开是商品选择器，选中即发送商品卡片——**这才是"淘宝式链接"在拼多多里的等价物。**

所以路线是：

- **v1（现在）**：文字给「商品名 + 价格 + 您要哪个我发您」，不发链接；
- **v1.5**：自动发商品卡片（点「商品」→ 搜 goodsId → 点发送），比文字脆弱但可做；
- **不做**：裸链接。

## 四、商品数据从哪来

| 阶段 | 方式 | 成本 | 时效性 |
|---|---|---|---|
| v1 | 手工导入 CSV / 后台粘贴 | 0 | 靠人更新 |
| v1.5 | 从商家后台「商品管理」页抓（同一浏览器会话） | 低 | 每天自动同步 |
| v2 | 开放平台商品接口 | 需资质 | 实时 |

**库存必须每天同步**，否则会出现"说有货、实际没货"的赔付。v1 先做「每天手动点一次同步」，v1.5 做自动。

## 八、模板库：从零开始，模板只是起点

已实现「工作台 → 知识库 → 标准模板库」：

- 默认**不导入任何模板**，商家可以完全从空库开始；
- 提供 20 条标准问答（发货/时效/快递/包邮/发票/退换/不发芽/发芽率/播种/温度/催芽/深度/规格/储存/施肥/病虫害/讲价…）；
- 每条都可以单独「添加」，也可以「全部添加」；
- 添加只是复制进知识库，**之后必须自己改**——模板里的数字（85%、16 点）是示例，不是规则。

## 九、称呼：做，但只做一层

**结论：做「店铺级一个称呼 + 只在首次回复带」，不做「按场景动态切换」。**

| 方案 | 复杂度 | 体验 | 结论 |
|---|---|---|---|
| 店铺级一个称呼（亲/亲亲/您好） | 极低 | 一致、像人 | ✅ 采用 |
| 按买家性别/年龄/情绪切换 | 高 | 容易翻车 | ❌ |
| 按品类切换（母婴叫宝妈） | 中 | 需要品类标签 | ⬜ v2 |

理由：同一个客服号忽冷忽热，比一直说「亲」更像机器人。而且称呼一旦动态化，就要维护一张「什么场景用什么称呼」的策略表——这张表会随品类膨胀，最终没人能说清。

实现：`config.salutation = { enabled, text, onlyFirst }`，引擎在**本次会话还没有客服发言时**才加前缀。已实测：首次回复「亲，有货的…」，第二轮不带。

## 十、商品卡片：已实现（模拟页）

![商品卡片](../docs/screenshots/desktop-product.png)

流程：面板上点「发卡片」→ 自动点页面「商品」按钮 → 在弹层里搜 goodsId → 选中商品 → 页面发出商品卡片。

定位策略（为真实页面预留）：

1. 按钮：可见、文案等于「商品」、且不含输入框的元素；
2. 弹层：从 `[data-goods-id]` 商品项向上找，第一个同时包含可见 `input` 的祖先；
3. 搜索框：**只在这个弹层里找**（页面左上角还有一个「搜索会话/订单号」，按 placeholder 找会打错地方——已踩过）；
4. 发送后清空搜索框，避免污染。

接真实页面只需要确认四个元素的结构：商品按钮、弹层容器、搜索框、商品项。
