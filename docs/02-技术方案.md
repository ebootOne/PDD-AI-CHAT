## 1. 架构：三层，传输层可替换

```
┌──────────────────────────── 商家本机 ────────────────────────────┐
│                                                                  │
│  Chrome（已登录 mms.pinduoduo.com）                              │
│  ┌────────────────────────┐        ┌──────────────────────────┐  │
│  │ 商家后台客服页（原样）  │◄──────►│ 客户端 preload-cs.js      │  │
│  │  · 读 DOM 拿会话        │  填输入 │  · 会话快照（左/右气泡）  │  │
│  │  · 写输入框 / 点发送    │  框/点发 │  · 悬浮面板 UI            │  │
│  └────────────────────────┘        └──────────┬───────────────┘  │
│                                               │ chrome.runtime    │
│                                    ┌──────────▼───────────────┐  │
│                                    │ background.js（SW）       │  │
│                                    │ 唯一出口：fetch 127.0.0.1 │  │
│                                    └──────────┬───────────────┘  │
│                                               │ HTTP             │
│  ┌────────────────────────────────────────────▼───────────────┐  │
│  │ server/index.js  (127.0.0.1:8787)                           │  │
│  │  · /api/reply   → engine.js（意图→检索→生成→风控→决策）     │  │
│  │  · /api/knowledge  /api/logs  /api/review  /api/config      │  │
│  │  · 静态：仅剩 API（网页控制台与模拟页已移除）                 │  │
│  └───────────┬───────────────────────────┬────────────────────┘  │
│              │                           │                       │
│      ┌───────▼────────┐          ┌───────▼────────┐              │
│      │ data/*.json    │          │ LLM（可选）     │              │
│      │ 知识/日志/复核  │          │ OpenAI 兼容 API │              │
│      └────────────────┘          └────────────────┘              │
└──────────────────────────────────────────────────────────────────┘
```

**为什么这么分**
- **传输层（客户端 preload）与决策层（server）解耦**：将来接开放平台 API，只换传输层，引擎和知识库不动。
- **content script 不直接请求 localhost**：MV3 里 content script 受页面 CORS 限制，统一走 background 的 `host_permissions`。
- **零依赖**：只用 Node 内置 `http`/`fetch`，没有 npm install，商家机器上直接 `node server/index.js`。

## 2. 一次回复的完整数据流

```
买家发消息
  → MutationObserver 命中（防抖 1200ms，自动模式才触发）
  → captureConversation()：找输入框 → 向上找聊天列 → 按"类名签名重复 + 垂直堆叠"分组出气泡
    → 按气泡中心 x 与列中心比较，判定 buyer / seller
  → POST /api/reply { messages, goods, mode }
  → engine.generate()
      ① 意图分类（正则，7 类）
      ② 风险识别（投诉威胁 / 索赔诉求 / 引流站外）
      ③ 知识检索（关键词 3 分 + 二元组重合 ×2 + 标题 2 分）
      ④ 生成：有 Key 走 LLM（JSON 契约）；无 Key 走规则候选
      ⑤ 输出侧违禁词过滤（逐条候选）
      ⑥ 决策矩阵
  → 返回 { suggestions[3], decision, reason, confidence, knowledge[] }
  → 面板渲染：候选 + 依据 + 决策理由
  → 人点「填入输入框」/「填入并发送」→ 原生 setter 写值 + 派发 input 事件 → 点发送按钮
```

## 3. 决策矩阵（这是产品的安全边界，不是技术细节）

| 条件 | 决策 | 说明 |
|---|---|---|
| 买家投诉 / 索赔 | **handoff** | 不给候选，直接进复核队列 |
| 知识库零命中 | **handoff** | 不编造，宁可不答 |
| 候选命中违禁词且全被过滤 | **handoff** | 输出侧二次拦截 |
| 买家提站外联系方式 | suggest | 给合规话术，但强制人工确认 |
| 规则模式且置信度 < 0.55 | suggest | 匹配太弱 |
| 模式 = suggest | suggest | 默认形态 |
| 意图不在白名单 | suggest | 只有 logistics/spec/usage 可自动 |
| 置信度 < 0.82 | suggest | 阈值可配 |
| 非工作时段 | suggest | 避免夜间无人值守乱答 |
| 触发限流 | suggest | 同会话 8s，全局 20 条/分钟 |
| **以上全过** | **auto_send** | 才允许自动 |

> 注意顺序：**风险判定在最前，自动判定在最后**。任何一条不满足都退回人工。

## 4. 置信度怎么来的（以及它为什么不可全信）

- 规则模式：`0.35 + log10(1 + score) × 0.9`，封顶 0.98。score 来自关键词与二元组重合。
- 模型模式：直接用 LLM 自报的 confidence，但**必须叠加输出侧过滤**——模型对自己的置信度并不可靠。
- 现状：0.82 这个阈值是拍的，**必须用真实会话回归校准**。校准方法：跑 200 条历史会话，人工标"能直接发/不能"，画一条阈值-准确率曲线。

## 5. DOM 适配：最大的技术风险，以及三条缓解

**风险**：拼多多客服页改版 → 选择器失效 → 面板读不到消息或发不出去。这是所有 DOM 方案的死穴，绕不过去，只能降低恢复时间。

缓解：
1. **不写死 class**：消息行靠"同一签名重复出现 + 垂直堆叠"识别，左右靠几何中心判定；
2. **把识别结果摊给用户看**：面板显示"识别 N 条消息"、买家最后一句；错了人一眼能看出，可以点「刷新」重试；
3. **诊断上报**：面板「诊断」按钮把当前 DOM 快照 + 识别摘要发到本机 `data/diag-*.html`，我拿到就能定位改选择器，不用让用户复述。

**尚未验证**：真实 `mms.pinduoduo.com/chat-merchant` 页面的 DOM 结构。目前只在本地模拟页验证了链路。**这是 v0.1 唯一的红灯项**，需要拿真实登录态跑一次诊断。

## 6. 失败模式与降级

| 故障 | 表现 | 降级 |
|---|---|---|
| 本地服务没起 | 面板顶部红条 | 明确提示启动命令 |
| LLM 超时/报错 | `llmError` 字段 | 自动退回规则候选 |
| 知识库无覆盖 | 无候选 | 转人工 + 复核队列 |
| 页面改版 | 读不到消息 | 面板提示 + 诊断上报 |
| 发送失败 | 输入框有内容但没发出去 | 人工回车兜底（我们只填不抢发送） |
| 服务被占用端口 | 启动失败 | `PDD_CS_PORT` 改端口 |

## 7. 安全与隐私（当前实现）

- 只监听 `127.0.0.1`，不对局域网/公网开放；
- 不读取、不存储 Cookie / 密码 / Token；
- 日志里手机号自动打码（`store.js: maskPhone`）；
- 配置接口不回传 API Key 明文；
- 数据落在 `./data`，删目录即清空，可备份可审计。
