# 知识缺口：对外体面，对内待办

> 买家问「什么快递公司」，工具回「这个问题我暂时没有准确的信息，怕说错了误导您」。
> 这不是兜底，这是**当着买家的面承认我们不知道**——商家看了会关掉这个工具。

---

## 一、归因（docs/16 五步）

| 字段 | 内容 |
|---|---|
| 买家原话 | 什么快递公司 |
| 回复原文 | 这个问题我暂时没有准确的信息，怕说错了误导您。 |
| 失败类型 | 立场错（把内部缺口暴露给买家）+ 三态用错（不知道 ≠ 这么说） |
| 还原诉求 | 他要一个能发货的确定感，不是要我们的知识库状态 |
| 缺失思维 | **缺口分流**：对外口径 / 对内待办，两条线分开 |
| 思维定义 | 输入=店铺事实类问题 + 库里没有 → 判断=对买家只能用“以实际为准”的真话，对商家必须生成待办 → 输出=体面回复 + 缺口记录 |
| 改哪一层 | policy（对外口径）+ store/API/客户端（对内待办） |

---

## 二、正确回复长什么样

**原则：不编具体事实，但也不说“我不知道”；用“以实际为准”的真话兜住。**

| 问题类型 | 对外口径 |
|---|---|
| 快递公司 | 亲，快递公司以实际发货为准哦，下单后订单里能看到物流信息。 |
| 发货时间 | 亲，发货时间以订单页显示为准哦。 |
| 到货时效 | 亲，到货时间以物流信息为准哦。 |
| 发票 | 亲，发票可以在订单页申请，具体以页面显示为准。 |
| 支付方式 | 亲，支付方式以下单页显示为准哦。 |
| 退换规则 | 亲，退换规则以平台售后页面显示为准哦。 |
| 售后 | 亲，售后可以在订单里申请，具体以平台规则为准。 |

这些句子都满足：**真实、不承诺、不暴露内部、不引入下一轮**。

## 三、对内：缺口必须变成待办

只体面不记录，商家永远不知道自己缺东西。所以每次命中缺口，同时写一条 `gaps.json`：

```json
{
  "courier": { "count": 3, "samples": ["什么快递公司", "发哪家快递"], "lastSeen": "..." }
}
```

客户端「工作台 → 知识库」顶部展示：

```
知识缺口（买家问过、库里没有）
3 次   什么快递公司 / 发哪家快递   快递公司   [补模板] [忽略]
```

- **补模板**：直接导入对应模板（停用），填【】后启用
- **忽略**：商家确认「我们不做这类问题」时清掉

**自动完成**：只要知识库里出现了对应类型的条目（模板已导入，哪怕还在待确认），
这条缺口下次刷新就自动消失——不会出现「点补模板提示已存在，缺口还杵在那」。

这就是「对外体面，对内待办」：买家那边一句不露怯，商家这边一条待办。

## 四、多个快递公司怎么办

模板改成支持「主 / 备选 / 偏远 / 指定」四种情况：

> 默认发【主快递，可写多个，如 中通/圆通 随机发】；【偏远地区】转【备选快递，如 邮政】。如需指定快递请备注，能否满足以发货为准。

商家可以写成：
- 单快递：默认发中通
- 多快递随机：默认发中通、圆通，随机发
- 分地区：江浙沪发中通，其他发邮政
- 可指定：可以备注顺丰，补差价 X 元

---

## 四半、格式：固定句式，不做“智能解析”

明确一点：**检索是关键词匹配，不会理解“中通/圆通随机发”背后的地区逻辑。**
知识库的答案会被原样发出去，所以：

- 多条快递的**排列顺序不影响命中**，只影响买家阅读；
- 想让系统按省份自动换快递，需要结构化字段（省→快递映射），不是自由文本能“智能识别”的。

因此模板统一成一个句式：

```
默认发【主快递，可写多个】；【偏远地区】转【备选快递】。如需指定快递请备注，能否满足以发货为准。
```

四种店型都能套：单快递 / 多快递随机 / 分地区 / 可指定。

## 五、验收

| 用例 | 必须满足 |
|---|---|
| 什么快递公司（未录） | 回公开口径；不出现「没有准确信息」；gaps 计数 +1 |
| 发哪家快递（未录） | 同上（同属 courier） |
| 什么快递公司（已录） | 按知识库事实回答；不再记缺口 |
| **反例**：你们地址在哪 | 不属于店铺事实缺口，仍按隐私口径回答，不套快递话术 |
