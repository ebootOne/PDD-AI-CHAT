# 产品需求：拼多多智能客服回复工具

> 角色：产品经理（产品设计）
> 版本：v0.1 ／ 日期：2026-11-05
> 上游依据：商家后台客服页实拍（沐风AI电商 v9.9.0 内嵌 mms 客服工作台）、种子类目店铺现状、商业化与资质约束（见 `03-商业化与资质.md`）

---

## 1. 用户与 job

**用户不是"一个客服"，是"一个人守 5~20 个店的人"。**

截图里左侧那一列店铺（四季/乡野/优种/丰/新农人/壮芽/种天下/磐叶）就是用户的真实工作台：一个人、多店铺、消息同时进。

他要完成的 job 只有一个：

> **在平台考核的时间窗内，把每一个买家的下一句话回出去，且不能回错。**

拆开是三个约束：
- **快**：平台考核 3 分钟人工回复率，超时掉分掉流量；
- **对**：说错尺码、说错发货时间、乱承诺赔付，换来的是纠纷和仅退款；
- **省**：90% 的问题是重复的（发货、发芽率、怎么种、包邮、能不能退），不该每次都现想。

## 2. 现状摩擦（从截图读出来的）

| 现象 | 背后的问题 |
|---|---|
| 左列 8 家店，每家的「回复」数字都在涨 | 切店成本高，切过去还要重新读上下文 |
| 「16 个对话待复核」「1 个商品问题待补全答案」 | 机器人答了，但不敢直接发，人得回头看一遍——**复核成本没有被解决，只是被集中了** |
| 「机器人 [商品说明书]」 | 知识来源是商品说明书，不是通用话术——**答案必须挂在商品上** |
| 「客服回复助手：您有 1 个商品问题待补全答案」 | 平台自己的机器人也有答不上的时候，缺口正是机会 |
| 右侧消费者面板：申请类型/退款金额/申请说明 | 售后类会话风险最高，最不该交给模型自由发挥 |

**结论：这个品类的胜负手不在"AI 会不会聊天"，而在"知识够不够准、敢不敢发、发错了能不能拦住"。**

## 3. 一句话定位

> 把店铺的商品知识和售后政策，变成**3 秒能发出去、且每条都有出处**的标准回答；拿不准的自动挑出来转人工。

不是"AI 客服机器人"，是**"人工客服的外挂大脑 + 复核台"**。

## 4. 核心闭环（3 步，一步不多）

```
打开客服页  →  AI 已把 3 条候选放在右侧  →  点「填入输入框」，回车发出
     ↑                                              ↓
     └──────────  不确定的进「待复核」，人处理  ←────┘
```

**硬规则**
- 主任务 ≤ 3 步；一屏一个主按钮（「生成回复」）。
- 默认「建议模式」：AI 只填输入框，**发送永远由人按**。
- 「自动模式」是进阶开关，默认关，且必须同时满足：意图白名单 + 置信度 ≥ 0.82 + 工作时段 + 限流未触发。
- 每条回答都带「依据」折叠区：命中了哪条知识、几分、为什么。没有依据就不给候选，直接转人工。

## 5. 功能取舍

| 功能 | 决策 | 理由 |
|---|---|---|
| 右侧悬浮面板（不改造原页面） | **做** | 平台页面天天改，重写一套界面等于给自己挖坑；叠加层最轻 |
| 3 条候选（标准/简短/安抚） | **做** | 同一句话在不同情绪下要有不同说法，但选择不能超过 3 个 |
| 「依据」可见 | **做** | 这是和通用 AI 的分水岭：让人 3 秒判断"这句能不能发" |
| 待复核队列 | **做** | 承接"不确定"的会话，而不是让 AI 硬答 |
| 知识库（关键词 + 正文） | **做** | 冷启动靠它，不靠模型；没配 Key 也能用 |
| 自动发送 | **做，但默认关** | 商用风险最高项；开关在本机，日志留痕 |
| 多店铺聚合面板（像沐风那样） | **延后** | 浏览器多标签天然隔离，先不造第二套会话列表 |
| 从商品链接自动生成"商品说明书" | **延后（v0.2）** | 已有采集能力可复用，但先把"回答"跑通 |
| 订单/物流实时查询 | **不做（v0.1）** | 需开放平台权限，资质未定 |
| 语音/图片理解 | **不做** | 成本高、场景少 |
| 情绪识别、客户画像 | **不做** | 好听但用不上，增加认知负荷 |

## 6. 三个方案对比（都已评估）

> 2026-11-06 定案：选 B（桌面客户端），A（浏览器扩展）已弃用。下表保留当时的评估记录。

| | A. 浏览器扩展 + 本地服务 | B. 独立桌面工作台（内嵌浏览器） | C. 服务市场官方应用 |
|---|---|---|---|
| 用户操作步数 | 打开原页面即可用（0 步安装后） | 打开另一个软件，重新登录 | 在平台内开通 |
| 上线时间 | 1~2 周 | 4~6 周 | 3~6 个月 |
| 资质门槛 | 低 | 低 | 高（企业+ISV+备案） |
| 数据风险 | 最低（不出本机） | 低 | 高（集中存储） |
| 页面改版抗性 | 中（选择器会失效） | 中 | 高（官方 API） |

**推荐 A**，理由：交付最快、数据最干净、和 C 不冲突（C 上线后 A 作为兜底）。B 是"再造一个沐风"，投入产出比最差。

## 7. 关键界面文案与状态

| 位置 | 文案 | 说明 |
|---|---|---|
| 面板标题 | 客服助手 | 不叫"机器人"，避免用户以为是全自动 |
| 模式标签 | 建议模式 / 自动模式 | 常驻可见，不允许隐藏 |
| 主按钮 | 生成回复 | 唯一的主动作 |
| 候选按钮 | 填入输入框 ／ 填入并发送 | 「发送」永远在第二位 |
| 低置信 | 需人工确认 | 不用"置信度不足"这种技术词 |
| 无依据 | 建议在拼多多页面直接转人工 | 给动作，不给解释 |
| 风险 | 风险信号：投诉威胁 | 直说 |
| 服务未启动 | 本地服务未启动：请先运行 node server/index.js | 说清楚怎么办 |

## 8. 验收

**功能验收**
1. 打开客服会话，右侧出现面板，10 秒内可读到买家最后一句；
2. 点「生成回复」→ 3 秒内出 3 条候选，且能看到依据；
3. 点「填入输入框」→ 内容进入输入框，人工回车能发出；
4. 买家说「投诉」→ 不给候选，提示转人工，进复核队列；
5. 买家问「加微信」→ 给合规话术，且不自动发送。

**业务验收（跑两周后）**
- 知识库覆盖率 ≥ 70%（会话能被至少一条知识命中）；
- 人工修改率 ≤ 30%（候选被直接采用的比例）；
- 单条会话平均处理时长下降 ≥ 30%；
- 零"AI 说错导致纠纷"事故。
