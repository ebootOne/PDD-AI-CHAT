# 商品说明书：按商品绑定，按节命中

> 背景：买家问「那要泡水吗」，工具却答成了通用催芽流程——因为它不知道问的是哪款。
> 白萝卜要泡、番茄可以不泡，一个通用答案必然错一半。

![说明书](../docs/screenshots/desktop-manual.png)

---

## 一、结论：说明书要「分节」，不要「整段发」

你提了两个方案：

| 方案 | 问题 |
|---|---|
| 识别到"想知道怎么用"就发整份说明书 | 买家只问一句"要泡水吗"，收到 500 字说明书，等于没答 |
| 按说明书内容精确回答 | 需要结构化，否则没法定位到"泡水"这一段 |

**采用第二个，但保留第一个作为兜底**：命中不到具体节时，发「章节清单」而不是全文；买家说"发说明书"才发全文。

---

## 二、数据结构：一个商品一份，分节

```json
{
  "goodsId": "1001",
  "title": "白萝卜种子",
  "sections": [
    {
      "title": "要不要泡水",
      "keywords": ["泡水", "浸种", "泡多久", "要泡吗", "催芽"],
      "content": "要泡水的。播前用 30℃ 温水浸种 4~6 小时，捞出沥干后直接播，不要泡过夜。"
    }
  ]
}
```

关键点：

1. **必须绑定 goodsId**——绝不跨商品推断，这是准确率的来源；
2. **每节带 keywords**——"泡水吗""浸种""泡多久"都能落到这一节；
3. **content 是可以直接发出去的话**——不是给人看的文档，是给买家看的回复。

---

## 三、优先级：说明书 > 知识库

```
买家问用法，且当前商品已知
  → 查这个商品的说明书
      → 命中某一节 → 直接发这一节
      → 没命中但明显在问"怎么用" → 发章节清单
      → 都没有 → 回落到知识库/商品/模型/兜底
```

**为什么说明书优先**：知识库是「全店通用」的（发货、退换），说明书是「这个商品」的。
问"要泡水吗"时，通用知识一定是错的。

---

## 四、实测：同一句话，两件商品，两个答案

```
=== 白萝卜 ===
买家：有白萝卜种子吗
工具：有货的，这几款都有：白萝卜、樱桃萝卜…
买家：那要泡水吗
工具：白萝卜种子：要泡水的。播前用 30℃ 温水浸种 4~6 小时，捞出沥干后直接播，不要泡过夜。
      [来源 manual · 命中节 section]

=== 番茄 ===
买家：你们有番茄吗
工具：有货的，就是这款：番茄种子…6.9 元，可以直接拍。
买家：那要泡水吗
工具：番茄种子：可以不泡。番茄干籽直接播也能出；想提前出苗，用 25℃ 温水浸种 6~8 小时，捞出催芽。
      [来源 manual · 命中节 section]
```

同一句"那要泡水吗"，答案相反且都对——因为绑定的是商品，不是话术。

## 五、多个情况怎么处理

| 情况 | 处理 |
|---|---|
| 同一商品有两节都相关（播种时间 + 播种深度） | 分差 < 1 时两节一起给 |
| 两节内容互相矛盾（不同季节/地区） | 只给分高的那节；分差太小则给章节清单让买家选 |
| 商品没导入说明书 | 回落到知识库，不猜 |
| 买家问的商品不在库里 | 不匹配说明书，走商品匹配/兜底 |

**原则：宁可给章节清单，也不把矛盾的两段一起发。**

## 六、界面上的「来源」是怎么来的

回复里的 `来源` 不是写死的文案，是接口返回的字段：

```json
{
  "source": "manual",
  "manual": { "goodsId": "1001", "mode": "section", "title": "白萝卜种子" },
  "intent": "usage",
  "confidence": 0.92,
  "cost": 1
}
```

| 字段 | 含义 |
|---|---|
| `source` | 这条回复由谁产生：`rule` 本地知识 / `product` 商品匹配 / `manual` 商品说明书 / `backend` 服务端模型 |
| `manual.mode` | `section` = 命中具体某一节；`summary` = 没命中节，给的是章节清单 |
| `manual.title` | 命中哪份说明书 |

**注意**：只有"当前商品已知"时才会出现 `manual`。
如果对话里还没确定商品（比如第一句就问"要泡水吗"），会回落到知识库（`rule`）——这是刻意的，避免跨商品乱答。

## 七、接口

```bash
# 读
curl http://127.0.0.1:8787/api/manuals?goodsId=1001

# 写（单个商品）
curl -X POST http://127.0.0.1:8787/api/manuals \
  -H 'Content-Type: application/json' \
  -d '{"item":{"goodsId":"1001","title":"白萝卜种子","sections":[...]}}'
```
