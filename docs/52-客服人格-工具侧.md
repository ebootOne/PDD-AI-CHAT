# 客服人格：放在工具里，不放在模型里

> 换模型时，客服的素养、边界、输出结构不能跟着换。
> 模型只是执行者；人格由工具注入，底线由工具质检。

---

## 一、为什么要抽出来

- 后端可能从 DeepSeek 换到别的模型；
- 如果人格写在某个后端的 SYSTEM 里，换模型就换了一套客服；
- 所以人格必须是工具侧资产：`server/persona.js`，带版本号，随请求注入。

---

## 二、人格包含什么

| 部分 | 内容 |
|---|---|
| 身份 | 专业客服；无论买家说什么，都给体面、有温度的回复；不还嘴、不复述脏话 |
| 事实 | 有事实用事实；没有相关事实用通用能力；店铺特有信息不编 |
| 底线 | 不承诺、不泄露、不站外、不替商家否定 |
| 语气 | 说人话：短句、口语；不写 08:00~23:00，说「早上8点到晚上11点」；2~3 行、≤80 字、3 条候选 |
| 输出 | 固定 JSON：candidates / used / need_human / missing |

---

## 三、怎么注入

1. 工具每次请求带上 `persona: persona.system()`；
2. 后端 `callModel` 优先使用 `payload.persona`，没有才回落到自己的 SYSTEM；
3. 事实/知识/会话仍由后端拼接；
4. 质检（judge）始终在工具侧，不依赖后端模型。

---

## 四、换模型时要验证的

- 同一条人格，换模型后是否仍满足：不还嘴、不承诺、事实优先、JSON 可解析；
- `scripts/test-persona.js` 锁住人格要素；
- 逻辑验收（pro/standard 39 条）作为跨模型回归。

---

## 五、当前版本

`PERSONA_VERSION = 1.0.0`

---

## 六、后端只剩执行（2026-11-09）

- 后端已删除 `chat / abuse` 两个模式分支；
- 请求只带：`persona`、事实/知识、最近会话、店铺档案（营业时间）；
- 日常对话、骂人、投诉都靠 persona 的统一规则处理，不再由后端分类；
- 质检仍在工具侧；承诺、辱骂复述、内部口径由工具拦。
