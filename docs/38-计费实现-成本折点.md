# 计费实现：token 成本 → 点数

> 一句话：模型回复按「真实 token 成本 ÷ (1−毛利率) ÷ 点单价」扣点，**不足 0.5 点按 0.5 点**；
> 本地模板固定 0.5 点。成本和毛利率只存在服务端，客户端与商家侧只看到点数。

---

## 一、公式

```
成本（元） = (命中输入×单价_hit + 未命中输入×单价_miss + 输出×单价_out) / 1,000,000 × 时段系数
原始点数   = ceil₃( 成本 ÷ (1 − 毛利率) ÷ 点单价 )
实扣点数   = max( 原始点数, 0.5 )
```

| 参数 | 值 | 位置 |
|---|---|---|
| 缓存命中输入 | 0.04 元/百万（高峰） | 服务端 `.env` |
| 缓存未命中输入 | 2 元/百万（高峰） | 服务端 `.env` |
| 输出 | 8 元/百万（高峰） | 服务端 `.env` |
| 时段系数 | 高峰 1.0；空闲 0.5 | 按北京时间自动判断 |
| 毛利率 | **75%**（售价 = 成本 ÷ 0.25） | 服务端 `.env` |
| 点单价 | 5000 元 / 600,000 条 ≈ 0.008333 元/点 | 服务端 `.env` |
| 精度 | 向上取整到 0.001 点 | 服务端 `.env` |
| 模型单条下限 | **0.5 点**（与本地同价） | 服务端 `.env` |
| 封顶 | **没有** | — |

> 注意：**加价 80%（×1.8）≠ 毛利 80%**。×1.8 的毛利率只有 44%。
> 要「5000 元至少赚 3500」，毛利率必须按 75% 算，也就是售价 = 成本 ÷ 0.25（4 倍成本）。

价格来源：[DeepSeek 模型 & 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)。
高峰=工作日 9:00–12:00、14:00–18:00；周末与其余时段半价。

## 二、实测样例（已确认事实）

一次真实 Pro 调用：输入 561（命中 256 / 未命中 305），输出 109。

| 项 | 计算 | 金额 |
|---|---|---|
| 命中 | 256 × 0.04 / 1e6 | 0.000010 元 |
| 未命中 | 305 × 2 / 1e6 | 0.000610 元 |
| 输出 | 109 × 8 / 1e6 | 0.000872 元 |
| 成本 | 合计 | **0.001492 元** |
| 售价（毛利 75%） | ÷ 0.25 | 0.005969 元 |
| 原始点数 | ÷ 0.008333，向上取 3 位 | 0.597 点 |
| 实扣（高峰） | 高于下限 0.5 | **0.597 点** |

正常长度的回复落在 **0.55~0.7 点**；只有 token 很少的短回复（成本低于 0.00125 元）
才会触底 0.5 点。长回答按成本继续往上，不封顶。

**本地模板**：0 成本，固定 **0.5 点/条**（兜底话术也按 0.5 点；没产出回复不扣）。

**模型调了但被质检换成兜底**：按 `max(0.5, 模型点数)` 扣——成本已经发生，
既不出现长回答倒贴，也不会出现「模型被丢弃还按模型价收」。

### 2.1 「5000 元至少赚 3500」怎么保证

因为它是一个**构造出来的恒等式**，不是靠估算：

- 售价 = 成本 ÷ 0.25 ⇒ 成本 = 售价 × 0.25；
- 所以任何一笔模型回复，成本最多占售价的 25%，毛利至少 75%；
- 本地回复成本≈0，毛利≈100%；
- 下限 0.5 只在 token 极少的短回复上把毛利**往上抬**，不会往下拉。

5000 元 = 600,000 点（0.008333 元/点）。按实测 0.64 点/条：

| 情况 | 可卖条数 | 模型成本 | 毛利 |
|---|---:|---:|---:|
| 全部走模型 · 0.64 点/条 | 937,500 | 1,250 元 | **3,750 元（75%）** |
| 短回复触底 0.5 点 | 1,200,000 | <1,500 元 | **>3,500 元** |
| 正常：模型率 45%、其余本地 | — | 更低 | **更高** |
| 长回答（原始点数 >0.5） | — | 占售价 25% | **固定 75%** |

结论：**任意 5000 元账单，模型成本 ≤1500 元、毛利 ≥3500 元**。
注意这是「相对模型调用成本」的毛利，不含服务器、人力、支付通道费。

## 三、落点

| 层 | 做什么 | 不做什么 |
|---|---|---|
| `pdd-cs-backend/src/pricing.js` | 读 `.env`、按时段算成本、算点数 | 不把成本返回客户端 |
| `pdd-cs-backend/src/server.js` | 返回 `billing.points`；成本与原始点数写服务端 `usage.jsonl` | 客户端日志不存成本 |
| `server/index.js` | 模型回复用 `billing.points`；本地回复用 `billing.localPoints` | 不再写死 1 点 |
| `server/quota.js` | 小数扣点，3 位精度，带容差 | 余额比较不用浮点直比 |
| 桌面端 | 显示 0.5 / 0.597 这样的小数点 | 不显示成本、毛利、毛利率 |

服务端 `.env` 可覆盖：`PRICE_HIT_PER_M`、`PRICE_MISS_PER_M`、`PRICE_OUT_PER_M`、
`IDLE_FACTOR`、`PRICE_MARGIN`、`POINT_VALUE_CNY`、`MIN_POINTS`、`MODEL_MIN_POINTS`、`POINTS_PRECISION`。

## 四、对商家怎么说

- 本地模板：**0.5 点/条**；
- 专业版：**按模型实际消耗扣点，最低 0.5 点/条**，答得越长、输入越多扣得越多；
- 没生成出回复不扣。

**不说**：成本、毛利率、token 单价、模型名。
