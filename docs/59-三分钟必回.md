# 三分钟必回（最高优先级产品规则）

> 拼多多考核 3 分钟人工回复率。**回复率是入场券，错误率是竞争力**：先保证每条买家消息都有回复，再优化答得对不对。

---

## 一、规则

1. 每条买家新消息，**3 分钟内必须发出至少一条**；
2. 宁可发安全兜底/答得不完美，也不能不发；
3. 有把握的候选优先发；没把握/被质检扣住时，发安全兜底；
4. 兜底不编事实、不承诺赔付/退款/到货、不泄露隐私、不复述辱骂。

---

## 二、实现

| 时机 | 动作 |
|---|---|
| 检测到新买家消息 | 建 `pendingAuto`，deadline = 现在 + 180 秒 |
| 生成完成且候选可发（auto_send / 过质检模型 / 兜底） | 立即发候选 |
| 生成完成但被扣住/无候选 | 约 0.5 秒后发安全兜底 |
| 生成报错/接口异常 | 立即发安全兜底 |
| 超过 180 秒仍未发出（生成卡住/发送失败） | 兜底计时器强制发安全兜底，失败每 30 秒重试 |

安全兜底：

> 亲，收到您的消息了，我帮您看看具体情况哈。

只表示“收到了、在看”，不承诺结果、不编事实。

日志：

```
auto_trigger → auto_result → auto_gate → auto_send_ok
                                      ↘ auto_hold_send / auto_deadline
```

---

## 三、边界

- 当前只监控**当前打开的会话**；别的会话来消息，页面不切换就看不到；
- 要做到“所有会话自动回”，下一步需要自动切未读会话（未实现）；
- 3 分钟是硬上限，不是目标；能 1 秒发就 1 秒发。

---

## 四、和“不编造”的关系

必回优先，但不等于必须编：
- 有事实 → 用事实答；
- 没事实 → 页面口径/安全兜底；
- 风险问题 → 先接住，不做越权承诺。

这样既保回复率，也不把错误率推到不可控。

---

## 发送通道（2026-11-10 实测）

- JS `click()` / CDP 鼠标点击都不触发拼多多发送；
- 主进程 `webContents.sendInputEvent` 发**可信 Enter** 才能发出去；
- 输入也必须用主进程 `insertText`，程序化赋值不会让发送按钮进入可发状态。

实测：

```json
{"fill":{"ok":true,"source":"pdd-trusted"},"send":{"ok":true,"source":"pdd-enter","waitedMs":400}}
```

预加载发送顺序：可信 Enter → 没清空再补可信鼠标点击 → 3 秒轮询。

## 事故修正（2026-11-10）

“必回”已细化为 **一条且仅一条**：

- 同一条买家消息只发一条；
- 同文案 2 分钟内不重复；
- 兜底 3 条轮换；
- judge 禁止“买家没发过的数字/单号”；
- 真实店铺暂停自动，先演示店验证。
