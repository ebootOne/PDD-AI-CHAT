# 需求逻辑与验收（给测试用）

> 用途：换一个会话/换一个人，只看这份文档就能判断"逻辑通不通"。
> 原则：**只验规则，不验话术**。话术可以换，规则不能破。

---

## 一、系统由三块组成

```
桌面客户端（Electron）        本地服务（:8787）            服务端（可选，:8798）
店铺分区 / 读页面 / 填输入框   知识·商品·说明书·兜底·计费      持有模型密钥
```

- 客户端不存模型密钥；模型调用只走服务端。
- 本地服务是唯一数据源：`data/*.json`。
- 没配服务端时，本地规则能答的照答，答不了的走兜底。

---

## 二、数据模型（测逻辑先看这四张表）

| 对象 | 关键字段 | 隔离维度 |
|---|---|---|
| 店铺 store | id / name / url / lastUrl / syncMeta | — |
| 商品 product | goodsId / title / price / priceMax / stock / status / **storeId** / category | 店铺 |
| 说明书 manual | goodsId / sections[] / **storeId** | 商品 |
| 知识 knowledge | title / keywords / answer / enabled / **storeId** / archived | 店铺（无 storeId = 通用，可归档） |

## 三、核心规则（编号即用例编号）

### 3.1 商品识别

| ID | 规则 | 怎么验 |
|---|---|---|
| P01 | 商品卡标题 → 反查商品库 | 回答里出现商品名或来自商品事实 |
| P02 | 商品未知时不合用别的商品的说明书 | source ≠ manual |
| P03 | 商品未知时不冒充"您买的这款" | 回复不含「这款/您拍的」 |

### 3.2 回答来源（优先级从高到低）

```
说明书（商品级） → 商品事实（价/库存） → 知识库（店铺级） → 模型 → 兜底
```

| ID | 规则 | 怎么验 |
|---|---|---|
| A01 | 问价给价格，区间写「元起」 | 含「元」；有 priceMax 时含「起」 |
| A02 | 问库存只答库存，不夹价格 | 含「有货/现货」，不含「元」 |
| A03 | 说明书分节命中 | source = manual |
| A04 | 说明书优先于知识库 | 鸟用品问题不应答出「发芽适温」 |

### 3.3 边界与承诺

| ID | 规则 | 怎么验 |
|---|---|---|
| C01 | 占位符【…】绝不发出 | 回复里不含 `【】` |
| C02 | 不给流程承诺 | 不含「我帮您查/稍后回复/安排人/转人工」 |
| C03 | 出一条就计费 | 任何产出可发送回复（含兜底）cost=1；无回复 cost=0 |
| C04 | 兜底不暴露内部 | 不含「知识库/资料里/模型」 |
| C05 | 关切兜底要贴题 | 问凭证答凭证、问安全答安全，不答库存/适用对象 |
| C06 | 没有口径也不编 | 港澳台/海外无配送知识时引导买家在下单页确认地址 |
| B01 | 退款先问原因 | 「我要退款」→ 问一句具体情况，不直接甩规则 |
| B02 | 说清问题给办法 | 买家说明破损/不发芽 → 给可执行的处理方向 |
| B03 | 坚持才给出口 | 仍坚持退款 → 告知订单页申请售后 |

### 3.3.1 语气（亲近但不轻佻）

| ID | 规则 | 怎么验 |
|---|---|---|
| T01 | 冷的陈述句要补语气词 | 报价/库存/快递句尾有 呢/哈/哦 |
| T02 | 疑问、致歉、指令、敏感信息不加 | 售后/发票/「请…」句尾不带语气词 |
| T03 | 加语气不得改事实 | 数字与否定词前后一致，否则原样返回 |

### 3.4 多店铺

| ID | 规则 | 怎么验 |
|---|---|---|
| S01 | 商品/说明书按店铺隔离 | `?storeId=` 过滤 |
| S02 | 知识按店铺隔离，同名本店覆盖通用 | 本店条目优先 |
| S03 | 通用知识不参与任何店铺回答 | `?storeId=` 返回里没有无 storeId 的条目 |
| S04 | 商品同步异常不覆盖 | 空数据 → skipped=empty |
| S05 | 知识可跨店复制，同名跳过 | copy 返回 added 数 |

### 3.5 客户端交互

| ID | 规则 | 怎么验 |
|---|---|---|
| U01 | 填写输入框后必须能清掉 | 有「清空草稿」按钮；换会话自动清 |
| U02 | 演练模式只填不发 | 不开自动时不会点发送 |
| U03 | 二级弹层关闭不影响下层 | 关说明书后工作台仍在 |
| U04 | 登录后自动进客服页 | 不用商家点菜单 |
| U05 | 店铺名自动取后台真名 | 不是「真实店铺」 |

## 四、怎么跑

### 一键逻辑验收（API 级）

```bash
node server/index.js &          # 本地服务
node scripts/logic-check.js     # 39 条检查（K01~K35）
```

输出 `PASS/FAIL`，有 FAIL 退出码 1。当前：**39 通过 / 0 失败（standard / pro 各跑一遍）**。

### 回归

```bash
node scripts/test-engine.js     # 引擎单测 35 条
node scripts/eval.js            # 评测集 19 条
```

### 真实页面

```bash
node scripts/capture-live-page.js   # 抓当前客服页结构
node scripts/sync-products.js       # 同步商品
```
