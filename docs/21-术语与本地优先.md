# 术语与本地优先（local-first）

> 一句话：**能本地答的，绝不调模型。** 本地命中同时决定毛利、延迟和稳定性，模型只服务长尾。

---

## 一、术语表（全项目统一用词）

| 术语 | 定义 | 口径 |
|---|---|---|
| **本地命中率**（local hit rate） | 由本地知识/商品/规则直接给出可发送回复的比例 | 本地回复数 ÷ 总回复数 |
| **模型调用率**（model call rate） | 一次回复触发服务端模型的比例 | 模型调用次数 ÷ 总回复数 |
| **兜底率**（fallback rate） | 既未命中本地、也未得到可用模型答案的比例 | 兜底条数 ÷ 总回复数 |
| **单条成本**（cost per reply） | 平均每条回复的模型成本 | 模型总成本 ÷ 总回复数 |
| **token 预算** | 单次模型调用允许的 token 上限 | 均值 ≤ 700，p90 ≤ 800 |
| **承诺面**（commitment surface） | 回复中对外承诺的动作集合 | 越小越好；全自动模式应为空集 |
| **可执行性** | 承诺的动作在运行时是否真的能执行 | 由 capabilities 判定 |
| **三态** | 知道 / 能查 / 不知道 | 不知道必须走兜底，不许空话 |
| **焦点** | 本轮新增的那一问 | 决定最小充分回答 |
| **槽位** | 问题里的实体（商品/地区/数量/时间） | 决定答案是否具体 |
| **归一化** | 口语/错字/省略 → 标准说法 | 提升召回 |
| **语境风险** | 用「诉求 + 条件」判断风险，而非关键词 | 防误伤与漏判 |
| **证据分级** | 已确认 / 暂定 / 建议 / 待确认 | 结论必须标注 |

## 二、本地优先的判定顺序

```
规则/知识库 → 商品目录 → 店铺声明 → 模型（仅长尾）
```

任一层给出**有依据**的答案就停，不往下走。

**默认：本地不匹配 → 调模型。** 只有两类例外不调：隐私问题（本地规则拒绝）、
以及会立刻被质检改写的威胁类。店铺事实（快递/价格/售后）本地没有时也会调一次模型，
但模型给不出店铺事实，最终仍走公开口径 + 缺口记录——这一步是为了守住“本地不匹配就交给模型”的统一原则。

四条停止条件（满足其一即不调模型）：

1. 本地有命中且置信度达标；
2. 命中来源是商品目录或说明书（权威数据，模型不得覆盖）；
3. 隐私问题（老板电话/地址等，本地直接拒绝）；
4. 回复注定要被质检改写（如威胁语境）。

## 三、KPI（内部）

| 指标 | 目标 | 现状 |
|---|---:|---:|
| 本地命中率 | 持续提升，不设硬指标 | 40 条 50% / 100 条 **75%** |
| 模型调用率 | ≤ 50% | 7.5% / 13% |
| 平均 tokens | ≤ 700 | 584 |
| 单条成本 | ≤ 0.001 元 | ≈ 0.001 元 |
| 兜底率 | 越低越好 | 40% / 10% |

> **准确率优先**：本地化只在“我们真能答对”的地方做。为了命中率硬答，比调模型更伤。

> 口径说明：40 条探测里含大量「知识本身没有」的问题（土壤 pH、推荐、对比、税率），
> 这些应归入能力缺口，不应拉低本地命中率 KPI。② 开始前先把「可答集合」定义清楚。

> 数字只进内部视图（AGENTS 第 12 条），商家端不展示。

## 四、提本地命中率的四件事（不动话术）

1. **知识覆盖率**：模板库 + 日志推荐，把高频问题补进知识库；
2. **召回质量**：归一化、同义扩展、商品结构化（价格/库存/规格直答）；
3. **置信校准**：去掉「自己跟自己打平」（重复条目去重）、按问题类型校验；
4. **少问模型**：能用目录算的（价格、库存、规格、运费）不推理。

---

## 五、反模式（禁止）

| 反模式 | 后果 |
|---|---|
| 为了提高命中率硬答 | 编造，违背硬规则 2 |
| 把模型当默认通道 | 成本失控、延迟上升、输出不稳定 |
| 用重复知识条目堆召回 | 置信度被打平，反而升级到模型 |
| 为省 token 把该给的事实说含糊 | 伤害商家体验，得不偿失 |

**原则：本地优先 ≠ 本地硬答。本地答不了，如实兜底，比编一个更便宜也更安全。**

## 六、验收

- 同一批 100 条随机问法，本地命中率不低于上一版；
- 模型调用率不高于上一版；
- 兜底率不上升（否则说明本地在“抢答”错误内容）；
- 回归：`test-engine` / `eval` / `desktop-e2e` / `desktop-e2e` 全绿。
