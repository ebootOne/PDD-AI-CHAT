# 术语与判断优先级（原“本地优先”）

> 一句话：**回复率（3 分钟必回）> 准确率 > 成本。** 不回复会触发平台考核/罚款，直接造成商家损失；本地/模型/规则都只是手段。

---

## 一、术语表（全项目统一用词）

| 术语 | 定义 | 口径 |
|---|---|---|
| **本地命中率** | 本地知识/商品/规则直接给出可发送回复的比例 | 观察指标，不是目标 |
| **模型调用率** | 一次回复触发服务端模型的比例 | 观察指标，不为省点硬压 |
| **兜底率** | 既未命中本地、也未得到可用模型答案的比例 | 越低越好 |
| **单条成本** | 平均每条回复的模型成本 | 护栏，不是决策者 |
| **token 预算** | 单次模型调用允许的 token 上限 | 均值 ≤ 700，p90 ≤ 800 |
| **承诺面** | 回复中对外承诺的动作集合 | 越小越好 |
| **可执行性** | 承诺动作在运行时是否真的能执行 | 由 capabilities 判定 |
| **三态** | 知道 / 能查 / 不知道 | 不知道必须兜底，不许空话 |
| **焦点** | 本轮新增的那一问 | 决定最小充分回答 |
| **槽位** | 问题里的实体（商品/地区/数量/时间） | 决定答案是否具体 |
| **归一化** | 口语/错字/省略 → 标准说法 | 提升召回 |
| **语境风险** | 用「诉求 + 条件」判断风险，而非关键词 | 防误伤与漏判 |
| **证据分级** | 已确认 / 暂定 / 建议 / 待确认 | 结论必须标注 |

---

## 二、判断顺序（2026-11-10 修正）

```
取事实 → 判断是否涉及指代/取舍/歧义/上下文
      ├─ 是 → 模型决策（可答 / 问哪一单 / 问哪一款 / 转人工）
      └─ 否 → 本地确定事实或模板可直接答
      ↓
质检 → 发送 → 3 分钟兜底
```

**本地直接答只适用于：**

1. 事实确定、无歧义（例如单商品价格、单订单状态、固定政策）；
2. 四模板/固定寒暄等确定性回复；
3. 3 分钟 deadline 到达时的安全兜底。

**必须交模型：**

- 多订单/多商品/多包裹的指代与取舍；
- “上次那个 / 那单 / 还有吗”等上下文指代；
- 需要判断“要不要问是哪一单/哪一款”；
- 事实冲突、跨来源取舍、政策与订单冲突；
- 任何本地规则需要靠穷举才能覆盖的问法。

> 本地能列出候选，不等于能决定选哪个；本地只供事实、校验和执行。

## 三、KPI（内部观察，不是优化目标）

| 指标 | 口径 |
|---|---|
| **3 分钟回复率** | **最高硬指标**：每条买家消息 3 分钟内必须有一条回复；不回复=考核/罚款 |
| 答错率 | 第二核心指标；必回前提下尽量降低，以黄金集/真实会话衡量 |
| 本地命中率 | 观察本地覆盖变化，不设硬指标 |
| 模型调用率 | 观察成本，不为了压低而牺牲回复率或准确率 |
| 单条成本 | 护栏：异常升高要查 |
| 兜底率 | 越低越好 |

> **先必回，再答对**：任何“等更准的答案”“省一次模型”“本地没命中”都不能成为不回复的理由。
> 不确定就发一条安全兜底；但不能用重复发送/错误内容换回复率。

---

## 四、提准确率的四件事

1. **事实覆盖**：商品、订单、包裹、政策、说明书结构化；
2. **歧义识别**：多候选时交模型判断，不本地猜；
3. **质检**：承诺、隐私、无依据、单位/订单错配；
4. **归因**：每次答错先定位缺的是切面/证据/断言/修复/范围，不修单句。

---

## 五、成本口径（谁的成本）

| 成本 | 承担方 | 作用 |
|---|---|---|
| 模型调用成本（约 0.0015 元/次） | **工具方** | 计入 75% 毛利定价，是内部经营指标 |
| 商家点数（本地 0.5 / 模型按 4 倍成本折点） | **商家** | 商家侧计费 |
| 本地优先/少调模型 | **工具方** | 提升毛利、降低延迟；**不能拿它换准确率或回复率** |
| 单条最多一次调用/超时不重试 | **工具方** | 防滥用和成本失控；3 分钟兜底仍必须发 |

> 结论：成本策略首先是**工具盈利与基础设施护栏**，不是“替商家省钱”的产品目标。
> 商家侧只体现点数；不能因为工具毛利更高，就把歧义、多订单、上下文判断压给本地。

## 六、反模式（禁止）

| 反模式 | 后果 |
|---|---|
| 为了提高本地命中率硬答 | 编造，违背硬规则 2 |
| 把多订单/多商品的取舍交给本地规则 | 猜错订单/商品 |
| 用“本地优先”压掉模型判断 | 准确率下降 |
| 为省点不调模型，导致答错 | 商家/买家体验受损 |
| 把测试原句塞进关键词表 | 下一句还错 |
