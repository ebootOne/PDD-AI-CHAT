# Pro 实测 · 第 1 轮

> 时间：2026-11-09 15:30
> 对象：`engine=pro`，店铺 `real`，商品：花椒木站杆 / 抽纸 / 白萝卜种子
> 方法：25 条真实问法走 `/api/reply`（`test:true`，建议模式），逐条看事实包、质检与回复
> 结论分级：✅ 可发 ｜ ⚠️ 可发但有问题 ｜ ❌ 不可发

---

## 一、结论

- **没有一条掉到兜底**，也没有引用非法（`factInvalid=0`）；
- **18/25 可直接发**，5 条可发但有瑕疵，2 条不可发：
  - ❌ 质检报告被答成「暂时没有质检报告」（ISS-019）；
  - ❌ 三连问只答了包邮，尺寸漏了（ISS-018 / ISS-020）。
- Pro 相对普通版的三个差异都成立（见第三节）。

❌/⚠️ 明细：

- **T15 质检报告**：模型答「暂时没有质检报告」。我们只是没有凭证数据，不能替商家说没有。

- **T02 库存**：回复里带截断长标题「天然花椒木站杆…虎皮小…」。

## 三、Pro vs 普通版（同题对比）

| 问句 | 普通版 | Pro | 差异 |
|---|---|---|---|
| 能开发票吗，几天能到 | 只答发票 | 发票 + 到货时效都答 | Pro ✅ |
| 发货了吗 | 「当天 16 点前发货」 | 标订单缺失 + 以订单页为准 | Pro ✅ |
| 有货么，好多钱 | 只报价 1.85 | 有现货 + 1.85 | Pro ✅ |

普通版的价值是快和便宜，Pro 的价值是「多问题、缺数据」时不出错。这三条正好落在分界线上。

## 六、建议修复顺序

1. **规格问法归一**（P1）：`understand` 的 spec 规则补「多大/多长/多高/尺寸/多少张/几张」；
   或在注册表补一条 `spec → product`，不动共用层也能先修 Pro。
2. **多意图覆盖**（P1）：拆句后即使 ask 归 other，也保留为「未覆盖子问题」，
   触发模型或标 `missing`；不能因为分类失败就只答一半。
3. **凭证类断言**（P1）：质检/报告问题禁止「没有 X」式结论，统一「以商品页标注为准」；
   judge 增加「否定性断言」检查或由 prompt 明确禁止。
4. **状态优先**（P2）：无订单数据时，先给「以订单页为准」，再给时效规则。
5. **标题收敛**（P3）：库存/价格回复用品类名，不用截断长标题。
6. **安全措辞**（P3）：去掉「放心使用」，保留「正常啃咬无碍」。

## 七、局限

- 单店铺、单商品卡，未覆盖多店铺切换；
- 没有真实订单，订单块只验证了「缺数据」分支；
- 测试会话均 `test:true`，自动发送链路未验证。
