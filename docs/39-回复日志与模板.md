# 回复日志与模板沉淀

> 入口：顶栏「工作台」→「回复日志」。
> 目的：让商家看见「刚才这条是怎么答的、扣了多少点」，并把答得好的沉淀成模板。

---

## 一、一条日志长什么样

```
11-09 06:15  露少小店6521  [模型]  [0.64 点]  [需确认]
买家：鹦鹉啃了会不会中毒
回复：天然花椒木材质，鸟类啃咬属正常行为，您留意下鹦鹉状态就好。
[加入模板] [编辑并加入]
```

- **来源**：本地知识 / 商品 / 说明书 / 模型 / 策略；
- **点数**：本地 0.5，模型按 token 成本折点（`docs/38`）；
- **决策**：自动 / 需确认 / 兜底 / 转人工。

## 二、两个筛选

| 控件 | 作用 |
|---|---|
| 当前店铺 / 全部店铺 | 只决定「看哪些日志」，不改变写入范围 |
| 加入模板的范围 | 决定「保存到哪」：当前店铺 / 整个工具（所有店铺） |

## 三、两个动作

### 3.1 加入模板（一键）

直接用默认值落库：

- 标题 = 买家这句话（截断 24 字）；
- 关键词 = 买家这句话；
- 回答 = 这条日志里的回复；
- 意图 = 日志里的 ask。

同名 + 同范围的模板会**更新**而不是重复新增。

### 3.2 编辑并加入

弹层里可以改标题、关键词、回答，再选范围，点「保存并加入模板」——
改完不用再回知识库手工建一条。弹层是二级弹层，保存后日志列表还在。

## 四、「整个工具」是什么

- 存成 `scope: 'tool'` + `storeId: ''`；
- 所有店铺的检索都会带上它（`server/index.js` 的 `kbForStore`）；
- 知识库里显示「通用」标签，编辑时保留 scope（不会一编辑就变成当前店铺）。

**边界（ISS-001）**：种子/历史条目的 `scope='global'` 是另一回事，**不参与跨店**。
只有商家在这里显式选「整个工具」才跨店。

**风险提示**：快递、时效、退换这类各店口径可能不同，选「整个工具」会让别的店也用它答。
弹层里已经写了这句提醒；后续可以加「只对某品类生效」。

## 五、已知限制

| 项 | 现状 |
|---|---|
| 日志条数 | 服务端最近 300 条，界面取前 100 条 |
| 搜索 | 暂无（可按店铺筛） |
| 一键加入的标题 | 直接用买家原话，可能口语化；要改就用「编辑并加入」 |
| 模板质量 | 日志里的兜底话术也能被加入——加之前看一眼回答 |

## 六、重复生成的抑制（2026-11-09）

### 现象

演练模式开着时，日志里会出现几十条一模一样的「什么时候发货」，每条都扣 0.5 点。

### 根因

自动模式靠「有没有读到买家消息」触发；演练模式**不会把回复发出去**，
买家那句一直处于「未答」状态，页面监控每次轮询都认为有新消息 → 反复生成、反复扣点。

### 两层去重

| 层 | 规则 | 效果 |
|---|---|---|
| 客户端 | 同一「会话地址 + 买家 + 最后一句」只自动生成一次；手动点「生成」也会记下这句 | 从源头不再发第二次请求 |
| 服务端 | 同一会话 + 同一句 + 同样消息数，15 秒内重复请求直接返回上次结果 | 即使客户端被改坏/双击，也不重复扣点、不写日志 |

服务端去重的返回带 `deduped: true`、`cost: 0`，余额不变；日志不新增。

### 历史数据

修复前的重复日志和扣点不会自动回滚；需要的话走充值接口补回（按实际重复条数）。
