# 事实可信度：来源 / 时效 / 冲突

> 模型可以判断“这条事实相不相关”，但判断不了“它对不对”。
> 正确性由工具负责：来源、更新时间、冲突。

---

## 一、每条事实带元数据

事实包里的每条现在是：

```json
{
  "id": "F1",
  "block": "product",
  "label": "价格",
  "text": "天然花椒木站杆：1.85 元起",
  "source": "catalog",
  "updatedAt": "2026-11-09T12:50:56.337Z"
}
```

| source | 含义 |
|---|---|
| catalog | 商品库（价格/库存/规格） |
| manual | 说明书 |
| knowledge | 知识库/政策 |
| order | 订单摘录 |
| profile | 店铺档案（如在线时间） |

---

## 二、时效：过期不报价

- 商品字段超过 **2 小时** → 不取价格/库存，标 `missing: product/price reason=stale`；
- 扩召回里原来会绕开这道检查，把过期价格塞进「商品」条；已补上同样的时效判断（2026-11-09 修复）；
- 结果：价格问题在数据过期时给页面口径，不报旧价。

---

## 三、冲突：不选边

同一字段出现两种不同说法时：

1. 按 `label` 分组；
2. 文本不一致 → 记 `conflicts`；
3. **把冲突项从事实包里全部剔除**；
4. 后端提示词加一行：

> 【冲突】价格/规格 的来源说法不一致，不要选一个，按页面口径答，不要编具体值。

5. 质检按“没有可用事实”处理，给页面口径。

例：

```
商品页：规格 18cm
说明书：规格 20cm
→ 两条都不给模型，只给「规格来源冲突，以页面为准」
```

---

## 四、边界

- 目前按 `label` 精确匹配，语义同义（包邮/免运费）还识别不了；
- 来源优先级还没有硬规则（谁覆盖谁），先做到“冲突不选边”；
- 冲突和时效都只影响事实包，不影响模型自己判断“这条事实相不相关”。

---

## 五、测试

`test-facts` M01–M04：

- 同字段两种说法 → 冲突并剔除；
- 冲突带来源；
- 商品过期 → 不报价；
- 商品事实带 source/updatedAt。

---

## 六、默认取数偏好，不硬性裁决（2026-11-09 修正）

之前做“一个字段一个权威来源”，但这也是穷举：

- 知识库完全可能覆盖商品库（活动价、临时调价、特殊说明）；
- 硬优先级会限制模型，遇到例外就错。

所以改成：

| 层 | 负责 |
|---|---|
| 工具 | 事实是否真实、是否过期、是否有冲突；冲突要标出来 |
| 模型 | 结合上下文选更具体/更新的那条；判断不了就给页面口径 |
| 质检 | 说了事实就必须有依据；不能编 |

- 取数仍有默认偏好（价格通常取商品库、政策取知识库），但**不是裁决**；
- 同字段多条说法不再丢弃，标记 `conflict: true` 后一起给模型；
- 提示词：【冲突】多条说法，优先更具体/更新的（如活动说明），判断不了按页面口径；
- 冲突不再算“缺失”，避免把可用事实误判成没有。

验证：M01 冲突标记保留、M05 价格多来源交给模型。

风险：模型可能选错。缓解：冲突标记 + 提示词 + 质检；仍不确定时进复核，而不是工具替模型选边。
