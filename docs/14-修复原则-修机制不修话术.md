# 修复原则：修机制，不修话术

> 起因：2026-11-05 用 40 条口语化买家消息探测，17 条答错或答空。
> 逐条改话术能让这 17 条变好看，但下一条换个说法还会错。
> 所以定一条硬规则：**每次修复，先找缺的是哪种判断能力，再改那一层。**

---

## 一、一句话

**看到的是「这句话答错了」，要找的是「这类话我们都答不对」的原因。**

问三句，答不上来就不许动手：

1. 这条暴露的是哪一层缺能力？（说法归一 / 实体槽位 / 问题焦点 / 会话状态 / 知识三态 / 证据强度 / 语境风险 / 组合计算 / 自我去重）
2. 同一类还有哪些问法会错？至少写出 3 条改写。
3. 改的是**规则**还是**这一句**？如果只对这一句生效，就是话术补丁，打回。

---

## 二、禁止清单（都是补丁，不是修复）

| 反模式 | 为什么不行 |
|---|---|
| 把测试原句加进 `keywords` | 下一条换个说法照样错，还会挤掉别的召回 |
| 为单个场景加 `if (text.includes('xxx'))` 特判 | 场景一多就是意大利面，且互相打架 |
| 直接改知识库答案“让它看起来对” | 知识库是商家的，不是用来迁就解析器的 |
| 把错误回复换个说法（措辞更客气） | 答错主题，客气也是错的 |
| 提高阈值/降低阈值让用例通过 | 调参不是修机制；先证明是对哪一层的补偿 |
| 新增功能抵消错误 | 违反「新增一个必须删/并/延一个」 |

---

## 三、验收：机制级回归，不是用例级通过

一条修复要同时满足：

1. **同类变体 ≥ 3 条**全部正确（不同说法、同义、省略、错字）；
2. **反例 1 条**不误命中（证明不是靠扩词表蒙对）；
3. 原有回归（`test-engine.js` / `eval.js` / `desktop-e2e.js`）不退化；
4. 修复说明写清：缺的能力、改的层、同类边界。

只有第 1 条是通过、没有 2-4，视为没过。

---

## 四、九种「缺的思维」

本次探测暴露的缺口，按层归类。以后遇到新问题，先归到其中一类，再谈怎么改。

| # | 缺的思维 | 症状（本次实测） | 该改的层 |
|---|---|---|---|
| 1 | **归一化**：买家说法 ≠ 知识库措辞 | 「多钱一袋」被判成规格；「咋种啊」说没有资料；「包邮不」答空话 | 查询理解层：同义/口语/错字/否定式归一，先于意图与检索 |
| 2 | **槽位**：问题里的实体没被提取 | 「发到黑龙江」说查不到；「河南」没有映射到周边；「买10袋」没有算量 | 槽位抽取 + 区域/数量表，答案按槽位参数化 |
| 3 | **焦点**：这轮问的是哪一句 | 三轮问「泡多久」都复读整段；「专票呢」复读普票段 | 答案切分 + 最小充分回答：只答新增那一问 |
| 4 | **状态**：会话里已答/待答/在追什么 | 问「两袋包邮吗」还在答价格；只有 `lastProduct` 一个变量 | 会话状态：当前话题、已答事实、未解决诉求 |
| 5 | **三态**：知道 / 能查 / 不知道 | 「土壤pH」答「核实一下」却标 0.9；「公司地址」答「帮您核实」 | 证据判定层：不知道就兜底 + 进复核，不许高置信空话 |
| 6 | **证据**：置信度=证据强度，不是模型自评 | 模型回「我帮您核实」也给 0.9，自动模式阈值形同虚设 | 置信度改为按命中证据/可核验程度计算 |
| 7 | **语境风险**：诉求+条件，不是子串 | 「急死了 到底发不发」因「发芽」命中，回了不发芽赔付话术；「再不发货我就退款」没判风险还引导退款 | 风险判定从词表升级为「诉求 + 条件 + 否定」结构 |
| 8 | **组合计算**：结构化数据运算 | 「两袋包邮吗」「一亩几袋」「和樱桃萝卜哪个好」都不会 | 商品结构化字段 + 少量计算/比较规则，不靠文本匹配 |
| 9 | **去重**：不重复自己 | 同一会话内连续复读整段答案 | 出候选前比对已发送内容，重复则改写或换角度 |

---

## 五、话术的边界

话术可以改，但只在**模板层**改，且必须对整类意图生效：

- 允许：语气档、长度、称呼、兜底措辞、禁用词表；
- 不允许：为某一条消息定制句子；
- 兜底话术必须承认「不确定」并给下一步，不许用更热情的措辞掩盖答不上来。

---

## 六、修复顺序（建议）

1. **P0 语境风险**：误伤会赔付、会掉店铺分，先修。
2. **P0 三态+证据**：置信度是自动模式唯一闸门，虚高等于没有闸门。
3. **P1 归一化+槽位**：直接决定召回率，且能覆盖大量长尾。
4. **P1 焦点+状态**：多轮体验，复读最伤「像真人」。
5. **P2 组合计算**：需要商品结构化，等数据齐了再做。

每修一类，先补 3 条变体 + 1 条反例进 `scripts/probe-accuracy.js` 的语料，再动代码。

---

## 七、复跑方式

```bash
node server/index.js
node scripts/probe-accuracy.js     # 产物：eval/accuracy-report.md
```

报告只标红旗（复读/空话/赔付口吻/疑似漏召回），最终判定由人做——**机器只负责把问题摊开，不负责宣布通过**。
