# 商业化与资质：功能 × 资质 × 技术可行性对照

> 角色：技术负责人（合规部分需法务/代办机构最终确认，本文是工程侧判断，不是法律意见）
> 查证日期：2026-11-05
> 结论标注：✅已确认事实 ／ 🟡暂定理解 ／ 🔵方案建议 ／ ❓待确认

---

## 0.1 直接回答你问的两个问题

**Q：调用 API 要不要公司资质？**

| 调谁的 API | 个人能不能调 | 要不要公司 |
|---|---|---|
| LLM（DeepSeek / 通义 / 智谱 / OpenAI） | ✅ 能，个人实名即可 | 不需要。但**面向商家收费**时需要能开票 → 要营业执照 |
| 拼多多开放平台 · 商品/订单类 | ⚠️ 个人可注册自研应用，但订单接口要**企业认证 + 商家授权** | 要 |
| 拼多多开放平台 · 上架服务市场 | ❌ 个人不行 | 要企业 + 应用审核 |
| 拼多多商家后台内部接口（Cookie/WebSocket） | 技术上能，**合规上不建议** | 不解决资质问题，反而增加风险 |

**Q：技术上可不可行？**

分三种，可行性完全不同：

1. **人工辅助（生成候选、人点发送）** → ✅ 今天已跑通，零资质门槛，风险最低；
2. **自动发送** → ⚠️ 技术可行，但平台规则风险最高，商用必须拿到授权或让商家明示自担；
3. **7×24 无人值守 / 多店服务端托管** → ❌ 需要官方 API，拿不到就只能做浏览器常开方案，商用价值打折。

**所以真正的卡点不是"能不能写出来"，是"能不能拿到拼多多开放平台的客服权限"。** 这件事本周就能验证，见 §4。

---

## 0. 一句话结论

**这个产品能不能商业化，不取决于代码，取决于三件事：主体（个人还是公司）、形态（本地软件还是 SaaS）、以及能不能拿到拼多多开放平台的服务商资质。**

在这三件事确定之前，任何"先做出来再补资质"的路径都会在收费那一刻卡住。

## 1. 三条商业化路径与资质门槛（先选路，再谈功能）

| | A. 本地工具（软件授权） | B. SaaS 多租户 | C. 拼多多服务市场 ISV |
|---|---|---|---|
> 2026-11-06：浏览器扩展已弃用，只保留桌面客户端。下表为历史比较。

| 形态 | Chrome 扩展 + 本机服务，数据不出电脑 | 云端部署，商家登录网页使用 | 官方应用，商家在服务市场订购 |
| 收款方式 | 卖激活码/授权文件 | 订阅制在线支付 | 平台代收 + 分成 |
| 主体要求 | 个体户或公司（要开票） | 公司 | 公司 + 平台审核 |
| 核心资质 | 营业执照 | 营业执照 + ICP备案 + ICP许可证/EDI + 等保二级 | 同 B + 开放平台服务商认证 |
| AI 合规 | 商家自备 Key，通常不构成"面向公众提供生成式AI服务" 🟡 | 平台统一提供模型 → 算法备案 + 大模型登记 ✅ | 同 B |
| 平台风险 | 中（工具在商家自己浏览器里跑） | 高（平台可认定为外挂批量操作） | 低（官方授权） |
| 上线速度 | 1~2 周 | 2~3 个月 | 3~6 个月 |
| 适合阶段 | **验证期 / 冷启动** | 规模化 | 长期正规化 |

🔵 **建议：A → C 两步走，跳过 B。**
先用 A 收第一批付费商家（现金流转正、验证知识库覆盖率），同时用真实数据去申请 C。B 的资质成本（ICP许可证 + 等保 + 算法备案）在没验证 PMF 之前是纯烧钱，而且 B 和 C 的能力高度重叠，没必要做两套。

## 2. 功能 × 资质对照表（逐条回答"这个功能要不要资质"）

| 功能 | 触发什么监管/平台规则 | 需要什么 | 结论 |
|---|---|---|---|
| 读取当前会话、生成回复草稿（不发送） | 无 | 无 | ✅ 零门槛，可先做 |
| 把草稿填入输入框，人工点发送 | 无（等同人工输入） | 无 | ✅ 零门槛 |
| **自动发送** | 《拼多多商家服务协议》通常禁止未经许可的自动化操作 🟡 | ISV 授权，或商家明示自担风险 | ⚠️ **最高风险项**，商用默认关闭 |
| 调用 LLM 生成文案 | 《生成式人工智能服务管理暂行办法》 | 见 §3 | 🟡 取决于谁提供模型 |
| 自建知识库、存商家话术 | 无（商家自己的经营资料） | 无 | ✅ |
| **存消费者会话/订单信息到自己的服务器** | 《个人信息保护法》 | 告知同意 + 最小必要 + 加密 + 留存期限 + DPA | ⚠️ SaaS 必须做，本地版可规避 |
| 多店铺账号聚合登录 | 平台账号安全规则 | 不建议代持密码；用商家本机登录态 | ⚠️ 代登录=高危 |
| 收费订阅（在线支付） | 《电信业务分类目录》 | 经营性互联网信息服务 → **ICP 许可证**（非备案） | ⚠️ 只有在线收费才触发 |
| 卖本地软件授权（离线激活） | 无 | 营业执照 + 软件著作权（建议） | ✅ 门槛最低 |
| 上架拼多多服务市场 | 开放平台服务商规则 | 企业认证 + 应用审核 + 预充值（按量计费） | ⚠️ 需企业主体 |
| 采集商品详情生成"商品说明书" | 平台数据规则 | 商家自己的商品，风险低 | ✅ |

## 3. AI 合规：什么时候需要备案？

关键分野是**"是否面向不特定公众提供生成式 AI 服务"**。

- **本地版 + 商家自备 API Key**：模型服务由商家与模型厂商直接签约，我方只提供软件。一般不构成"生成式人工智能服务提供者" 🟡，但**不能替商家做内容审核兜底**，所以产品里必须保留输出侧违禁词过滤（已在 `server/engine.js` 实现）。
- **SaaS 版 + 平台统一提供模型**：我方向不特定商家提供生成内容 → 构成服务提供者 ✅，需要：
  1. **算法备案**（深度合成，10 个工作日内）
  2. **大模型登记**（调用已备案模型的，做登记即可）
  3. **AI 生成内容标识**（显式 + 隐式水印）
  4. **投诉举报入口 + 处理时限**
  5. 内容安全：输入检测、输出二次检测、日志留存

依据：广悦律所《产品接入第三方AI大模型的合规义务》明确"即使通过 API 调用已备案模型，运营主体仍对输出内容承担主体责任"，并列举了重庆九龙坡网信办对"开山猴AI写作"的行政处罚案例。

**工程含义**：`server/engine.js` 里的 `forbiddenOutput` 过滤 + `review.json` 复核队列不是"锦上添花"，是**商用前置条件**。SaaS 版还必须补：内容标识、举报入口、日志留存 ≥ 6 个月。

## 4. 拼多多平台：必须去验证的一件事

所有第三方客服工具的生死线是：**拼多多开放平台到底给不给"客服消息"权限。**

- 已确认：拼多多开放平台**允许个人注册自研应用**，但**订单类接口需要企业认证 + 商家授权**；自研不冻结保证金，但要**预充值**（云内约 0.01 元/百次）；服务市场 ISV 门槛相对最低（0~5000 元）。来源：[五家开放平台认证门槛对照](https://developer.aliyun.com/article/1751134)
- 未确认：是否存在 `客服会话/客服消息` 类目与权限。目前检索到的"官方客服 API"说法（如 `pdd.customer.service.message.send`）**没有在开放平台文档中找到对应条目**，不能采信 ❓。

🔵 **行动项（本周就能做，成本 0）**：
1. 用公司/个体户主体注册开放平台，创建一个"自研应用"；
2. 在权限申请页搜索"客服 / 会话 / 消息"，截图留证；
3. 结果决定技术路线：
   - **有权限** → 走官方 API（稳定、合规、可按量计费），当前 DOM 方案降级为兜底；
   - **无权限** → 只能做"人工辅助工具"，自动发送必须弱化甚至删除。

> 这一步不做，后面所有架构讨论都是空中楼阁。

## 5. 技术可行性：三条路线打分

| 维度 | 浏览器扩展 + DOM | 内部接口 + Cookie/WebSocket | 开放平台官方 API |
|---|---|---|---|
| 今天能否跑通 | ✅ 已跑通（本地模拟页） | ✅ 有开源先例 | ❓ 权限未知 |
| 稳定性 | 中（页面改版即失效） | 中低（签名/风控/协议变更） | 高 |
| 合规性 | 中（用户自己浏览器） | **低**（代持 Cookie，易被判外挂） | 高 |
| 资质门槛 | 低 | 低但风险高 | 企业 + 审核 |
| 多店铺 | 多标签页 | 服务端多实例 | 服务端 |
| 7×24 无人值守 | ❌ 需浏览器开着 | ✅ | ✅ |
| 商用建议 | **Phase A 主力** | ❌ 不建议商用 | **Phase C 目标** |

**结论**：现阶段扩展方案是唯一"今天能交付、且不碰用户凭据"的路径；它同时也是 Phase C 的降级兜底（官方 API 挂了还能用）。**不要做 Cookie 网关**——代持商家密码/凭据，一旦出事是刑事责任级别的风险，收益不匹配。

## 6. 分阶段落地与资质清单

### Phase A（现在 ~ 第 4 周）：不收费内测
- 交付：扩展 + 本地服务 + 知识库（当前代码）
- 资质：**无需任何资质**（不收费、不集中存储、商家自备 Key）
- 目标：3~5 家店跑两周，拿到"知识库覆盖率"和"人工修改率"两个数

### Phase B（第 5 ~ 12 周）：本地版收费
- 交付：激活码 + 自动更新 + 崩溃上报
- 需要：**营业执照**（个体户即可）、**软件著作权**（建议，1~2 个月下证）、软件许可协议
- 不需要：ICP 许可证（不提供在线服务）、等保（不存数据）
- 定价参考：按店铺数/年，或按"自动回复条数"套餐（对标沐风的"剩余天数 + 会员等级"）

### Phase C（第 13 周起）：服务市场 / SaaS
- 需要：公司主体 → 开放平台服务商认证 → ICP备案 →（若在线收费）ICP许可证 →（若存消费者数据）等保二级 →（若自建模型服务）算法备案 + 大模型登记
- 预算粗估 🟡：ICP许可证 1~3 万（代办）、等保二级 3~8 万、算法备案 0（自办但耗时 1~2 月）、服务市场预充值按量

## 7. 产品必须现在就为"资质"改的三个设计

1. **自动发送默认关闭，且不可远程开启**——开关必须在商家本机，日志记录"谁在何时开启"，出事可举证。
2. **数据本地优先，云端只存"脱敏统计"**——会话原文不出本机，SaaS 化时也先做"端侧推理 + 云端只下发知识库"。
3. **每条回复留"依据"和"人工是否修改"**——既是产品差异点，也是合规证据链（证明 AI 没有脱离知识库乱说）。
