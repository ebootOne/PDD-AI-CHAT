# 回复规则：不合理 → 先归因思维，再定义思维

> 规则 7 管「怎么修」（修机制不修话术），规则 8 管「修成什么样」（先商人再 AI）。
> 这条规则管**入口**：看到一条不合理的回复，第一步该干什么。
>
> 一句话：**不许对着这句话改这句话。先回答「它缺了哪种思维」，再把那种思维定义成能判断、能验收的规则。**

---

## 一、什么算「回复不合理」

满足任意一条即触发，必须走本流程：

| 类型 | 表现 | 例子 |
|---|---|---|
| 答错主题 | 问 A 答 B | 「收到货坏了」→ 回答到货时效 |
| 答非所问 | 话题对，问题没答 | 「专票税率多少」→ 只讲开票流程 |
| 空话 | 只承诺去查，没有结论 | 「我帮您核实一下，稍后回复」 |
| 立场错 | 劝退、甩锅、冷处理 | 「等不了可以申请退款」 |
| 越界 | 编造、打包票、泄露 | 「河北现在这个温度基本合适」 |
| 复读 | 同一会话重复整段 | 三轮问泡多久，三轮同一段 |
| 决策错 | 该兜底却自信、该转人却给候选 | 知识库没有还标 0.9 |

## 二、五步归因法（顺序不能跳）

1. **还原诉求**：写下“正常人听到这句话，会认为他在要什么”，一句话。
2. **归类失败**：对应上表哪一类？可以叠加（如“答错主题 + 立场错”）。
3. **定位缺失思维**：从下面十种里选，**只能选已有的或新增并命名**，不许写“要更聪明”。
4. **定义思维**：写成 `输入 → 判断 → 输出` 三行，必须能被代码执行或用一句话让人复核。
5. **验收**：3 条同类变体 + 1 条反例 + 老回归不退化；反例不过说明规则在乱杀。

第 4 步是关键：**“要理解买家”不是思维，“先抽问题类型，再校验回复里有没有对应答案信号”才是。**

## 三、十种思维（缺哪种，补哪种）

| # | 思维 | 它要回答的问题 | 缺了会怎样 | 现在落点 |
|---|---|---|---|---|
| 1 | 归一化 | 买家这个说法，等价于哪种标准说法？ | 换个说法就查不到 | `understand.normalize` |
| 2 | 槽位 | 话里带了哪些实体（地区/数量/商品/时间）？ | 答得笼统、答错地区 | `understand.extractSlots` |
| 3 | 焦点 | 这一轮新增的到底是哪一问？ | 整段复读 | **未做** |
| 4 | 状态 | 这个会话已经答过什么、还欠什么？ | 话题漂移、重复 | 只有 `lastProduct` |
| 5 | 三态 | 我是知道、能查、还是不知道？ | 空话当答案、高置信乱答 | `judge` 无依据/未答上 |
| 6 | 证据 | 这句话的依据是哪条知识/哪个商品？ | 模型自由发挥 | `judge` 依据校验 |
| 7 | 语境风险 | 这是真投诉，还是拿投诉施压？ | 误转人工 / 漏判威胁 | `understand.threat` |
| 8 | 商人立场 | 这句话对商家是加分还是减分？ | 劝退、甩锅 | `judge` 劝退/威胁 |
| 9 | 边界 | 有没有超出“我能说”的范围？ | 承诺、编造、泄露 | `judge` 越界承诺 |
| 10 | 去重 | 这句话是不是刚说过？ | 复读 | **未做** |

3、4、10 目前是空的——这是当前体验最差的三块。

### 示例：专票税率（当前未修，先立卡）

| 字段 | 内容 |
|---|---|
| 买家原话 | 专票税率多少 |
| 回复原文 | 可以开发票：电子普票…专票需要提供一般纳税人资料，走对公流程 |
| 失败类型 | 答非所问 |
| 还原诉求 | 他要一个数字：税率/税点是多少 |
| 缺失思维 | 焦点 + 三态 |
| 思维定义 | 输入=问题；判断=问题里是否含“数值/比例/时限”类限定词（税率、几个点、多少天、多少钱）；输出=回复必须出现同维度答案，否则判“未答上”，走兜底或转人工 |
| 改哪一层 | `understand`（抽限定词）+ `judge`（校验维度覆盖） |
| 变体 ×3 | 「专票几个点」「开专票税率是多少」「普票和专票税率一样吗」 |
| 反例 ×1 | 「能开专票吗」——不含数值限定，按开票流程答即可，不该被拦 |
| 回归结果 | ✅ 2026-11-05 已实现：3 变体（专票税率多少 / 专票几个点 / 开专票税率是多少）全部 0 点兜底，反例「能开专票吗」正常按开票流程答；`eval` 19/19、`test-engine` 35/35 未退化 |

## 五、三条禁令

1. **禁止只改文案**：把“不能”改成“暂时无法”，问题还在。
2. **禁止单句特判**：`if (text === '专票税率多少')` 这类分支，一律打回。
3. **禁止用礼貌掩盖不知道**：越客气地答非所问，越像骗子。

---

## 六、和现有机制的关系

```
买家话 → understand（思维 1/2/7）→ engine（生成）→ judge（思维 5/6/8/9）→ 计费/复核
```

新增一种思维时，只有三个去处：`understand`、`judge`、或新开一层。**不许散落在话术模板里。**

---

## 七、判定「修好了」的口径

- 同一类 3 种说法都过；
- 1 个反例不误伤；
- 老回归（`test-engine` / `eval` / `desktop-e2e`）不退化；
- 兜底/改写同样计费（本地 0.5 点；模型按成本折点），但必须让人一眼看出“它没答上”（reason + costReason 可查）。

四条缺一，不算修好。
