# 决策：事实兼容守卫

- 日期：2026-11-11
- 状态：已采纳
- 关联：`server/answer-guard.js`、`server/judge.js`

## 背景

20 条真实买家上下文里：
- 库存/品种题被订单状态回答；
- 多订单只答一单；
- 尾号重复默认第一单；
- 已退款单只答“看页面”。

提示词调整后仍未解决。

## 判断

不是生成能力不足，而是“事实和问题类型不匹配”没有校验。  
回滚过一次“事实兼容重答”（0002），因为二次回答被 judge 误杀。

## 方案

新增 `answer-guard`，只拦截明显不匹配：
- 库存/品种/价格/规格题出现订单状态 → 安全反问或页面口径；
- 多订单只答一单 → 列出订单问哪一单；
- 尾号重复 → 不默认第一单；
- 点名已退款单 → 明确退款。

不生成新事实，不改模型选择的业务答案；只做最后一道校验。

## 验收

- `test-answer-guard` 6/6；
- 20 条真实问题：库存题不再答订单，退款单能说明退款，多单会问哪一单；
- Pro 39/39、standard 39/39、judge 15/15、auto 7/7、多订单 6/6。

## 代价

- 部分问题从“直接答”变成“问哪一单/哪款”；
- 真实解决率仍需线上验证；
- 不能替代模型选事实，只是安全网。
