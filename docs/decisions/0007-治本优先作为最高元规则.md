# 决策：治本优先作为最高元规则

- 日期：2026-11-13
- 状态：已采纳
- 关联：AGENTS.md

## 背景

连续多轮修复都在补“当前话术/当前订单”，没有解决状态完整性、模型证据和统一澄清门。

## 判断

治本不是 P0-4，不参与线上回复优先级；它是所有设计与修复的最高元规则。

线上：P0-1 先回复。
工程：先定义类、缺层、验收变体，再改代码。

## 硬门

- 禁止为单个说法/订单/商品加分支；
- 类问题必须落到可复用层；
- 验收必须含未见变体；
- 新机制接管后删除旧补丁。

## 结果

以后任何修复先过此门；过不了不进入实现。

## 退款动作重构

- 订单状态：个人订单 + 待支付订单统一采集；
- 模型输出 action，带 orderNo/slots；
- 本地新增 action-validator：订单存在、多单需明确、待支付/已退款拦截、槽位完整；
- 证据不足统一澄清；
- 删除 index 内散落的多单/待支付/商品名补丁；
- 本地完整命令模板只生成 action，不直接执行；
- K29/K30 通过；Pro 38/39（K22 语气波动）。
