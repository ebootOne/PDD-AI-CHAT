# 决策：实体-属性契约第一阶段

- 日期：2026-11-12
- 状态：进行中（影子校验）
- 关联：`server/answer-contract.js`、`server/context.js`

## 背景

`answer-guard` 是场景安全网，根因是事实没有实体/属性、模型回答没有声明属性。

## 本阶段

- context 事实增加 `entity/attrs`；
- 后端返回 `target.entity/attribute`；
- 新增 `answer-contract`，按 ask 期望属性校验 used 属性；
- 先影子记录，不改变回复。

## 验证

- 20 条真实问题中，库存题“订单事实”被契约标记；
- “另外两单退款”被误判为退货政策，已把 order_status 纳入退货/售后属性；
- `test-answer-contract` 7/7。

## 下一步

- 用 target 强制模型声明属性；
- 属性错配时用 need/重答，而不是继续加 guard；
- 契约稳定后删除 answer-guard 业务分支。

## 第二阶段（已执行）

契约不再只记录：
- `!ok` 时按期望属性取事实，带 `phase=answer` 重答一次；
- 库存/规格题附加“订单商品线索”，避免模型说“店铺没这款”；
- 重答后再次校验属性；
- answer-guard 仍作安全网，尚未删业务分支。

验证：Pro 39/39、contract 7/7、judge 15/15、guard 8/8、auto 7/7、多订单 6/6。

## 第三阶段（文本属性校验）

- 契约增加文本属性：库存题文本是订单状态且没有库存表述 → 判定错配；
- 库存题重答后已验证输出商品库存，不再答“已发货”；
- 20 条真实样本：库存题不再答订单，多单/退款稳定；
- answer-guard 仍保留，契约尚未完全替代。

## 第四阶段（替代产品分支）

- 契约增加价格/规格文本属性校验；
- 删除 answer-guard 的库存/价格/规格分支；
- 库存题错配由契约重答接住，自动模式可 auto_send 正确库存；
- answer-guard 只保留：多订单未覆盖、尾号重复、已退款单、配送绝对否定。

## 第五阶段（契约兜底）

- 重答后仍属性错配，不再发错误内容；
- 契约按期望属性给安全问句/页面口径；
- 产品分支 guard 已删除，库存/价格/规格由契约接管；
- 20 条真实样本：库存题不再答订单，重答失败也有安全兜底。
