# 决策：实体-属性契约第一阶段

- 日期：2026-11-12
- 状态：进行中（影子校验）
- 关联：`server/answer-contract.js`、`server/context.js`

## 背景

`answer-guard` 是场景安全网，根因是事实没有实体/属性、模型回答没有声明属性。

## 本阶段

- context 事实增加 `entity/attrs`；
- 后端返回 `target.entity/attribute`；
- 新增 `answer-contract`，按 ask 期望属性校验 used 属性；
- 先影子记录，不改变回复。

## 验证

- 20 条真实问题中，库存题“订单事实”被契约标记；
- “另外两单退款”被误判为退货政策，已把 order_status 纳入退货/售后属性；
- `test-answer-contract` 7/7。

## 下一步

- 用 target 强制模型声明属性；
- 属性错配时用 need/重答，而不是继续加 guard；
- 契约稳定后删除 answer-guard 业务分支。

## 第二阶段（已执行）

契约不再只记录：
- `!ok` 时按期望属性取事实，带 `phase=answer` 重答一次；
- 库存/规格题附加“订单商品线索”，避免模型说“店铺没这款”；
- 重答后再次校验属性；
- answer-guard 仍作安全网，尚未删业务分支。

验证：Pro 39/39、contract 7/7、judge 15/15、guard 8/8、auto 7/7、多订单 6/6。

## 第三阶段（文本属性校验）

- 契约增加文本属性：库存题文本是订单状态且没有库存表述 → 判定错配；
- 库存题重答后已验证输出商品库存，不再答“已发货”；
- 20 条真实样本：库存题不再答订单，多单/退款稳定；
- answer-guard 仍保留，契约尚未完全替代。

## 第四阶段（替代产品分支）

- 契约增加价格/规格文本属性校验；
- 删除 answer-guard 的库存/价格/规格分支；
- 库存题错配由契约重答接住，自动模式可 auto_send 正确库存；
- answer-guard 只保留：多订单未覆盖、尾号重复、已退款单、配送绝对否定。

## 第五阶段（契约兜底）

- 重答后仍属性错配，不再发错误内容；
- 契约按期望属性给安全问句/页面口径；
- 产品分支 guard 已删除，库存/价格/规格由契约接管；
- 20 条真实样本：库存题不再答订单，重答失败也有安全兜底。

## 第六阶段（覆盖/尾号/退款进入契约）

- 契约增加：多订单覆盖、尾号重复、点名退款单说明；
- answer-guard 只剩配送绝对否定安全网；
- 最终文本再验一次，避免 judge/guard 替换后绕过契约；
- 20 条真实样本：泛问发货/到货会问哪一单，具体单正确，退款单明确退款，库存题正确。

## 第七阶段（覆盖/退款/文本清理）

- 多订单覆盖、尾号重复、已退款说明进入契约；
- 泛问多单 → 问哪一单；具体单/退款单正常答；
- 最终文本清理：规格答案去掉“已发货/申通尾号”等冲突从句；
- answer-contract 15/15，Pro/标准 39/39，guard 3/3，多单 6/6。

## 第八阶段（target 生效）

- 人格不再覆盖 Pro 提示词，target 已由模型输出；
- 最终契约复核使用 target；
- 没有对应属性事实时，不因 target 缺失误杀（到货/政策类）；
- Pro/标准 39/39、contract15/15、guard3/3、judge15/15、auto7/7、多单6/6。

## 第九阶段（实体校验）

- target.entity 具体到商品/订单，不再只写泛称；
- 契约校验 target 实体是否对应 used 事实；
- 商品题进一步校验 target 商品是否与买家订单商品同一款；
- 不一致 → 问哪款/页面，不拿别的商品库存冒充。

## 第十阶段（claims 级）

- Pro 输出 claims(factId/attribute/value)；
- 契约逐条校验 factId 存在、属性匹配、claim 属于 used；
- target.entity 具体到商品/订单，并校验与 used/订单商品一致；
- 证据/地域题跳过商品属性契约，避免误杀；
- contract 20/20；Pro 38/39（K33偶发问哪一单，直接请求正常）。

## 第十一阶段（回答商品实体校验）

- 商品题如果回答里出现的是别的在售商品，而不是买家订单商品 → 契约拦截；
- target 实体与 used/订单商品不一致 → 安全问款；
- contract 21/21；Pro/标准 39/39；auto 7/7；多单 6/6。

## 第十二阶段（指代解析 / 商品检索）

- 新增 `reference.js`：先解析当前商品/订单商品/历史话题/目录候选，再决定答还是问；
- 新增 `product-index.js`：商品按标题/规格/别名检索 top-K，不再把全店前 8 个塞给模型；
- 能确定商品但目录没库存 → 答该商品页面口径，不泛问“哪个商品”；
- 只有没有指代且多候选时才允许问哪款；
- reference 4/4；Pro/标准 39/39；多单 6/6。
