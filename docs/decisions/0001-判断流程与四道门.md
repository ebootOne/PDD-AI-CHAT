# 决策：判断流程与四道门

- 日期：2026-11-11
- 状态：已采纳
- 关联提交：本次提交

## 背景

多次出现“用户提方案 → 先实现 → 出问题 → 再补规则”的循环。  
根因不是不会分析，而是默认把用户方案当需求执行，缺少独立判断和验证门。

## 判断结论

部分成立：加“要独立思考”的规则不够，必须把判断变成流程门槛。

## 前提

- 架构/范围/规则/成本变更才适用；
- 普通低风险小修可直接改，但仍自审；
- 用户明确说“先判断”或“开始”时，按门槛检查。

## 反例/失败场景

- 只写规则、不阻断动作 → 仍然先改代码；
- 反方 agent 与主 agent 共享同一盲点 → 误判“通过”；
- 判断记录写得很长但没有验收标准 → 形式主义；
- 所有小修都走四道门 → 效率过低。

## 最高原则影响

- P0-1：判断门防止“为了准确不回复”的改动直接上线；
- P0-2：反方评审和验收标准减少错误回复；
- P0-3：要求说明“真实解决”，防止只改话术。

## 被否掉的方案

- 只加一句“要独立判断” → 不可执行；
- 全部交给 LLM judge → 无法保证致命错误；
- 所有改动都走四道门 → 过度流程。

## 验收标准

- AGENTS 有判断先行、反方评审、验收先行、决策日志四条；
- `docs/66-判断流程.md` 可执行；
- 本次规则变更本身有决策日志。

## 结果/复盘

待后续架构变更验证：是否真的先判断再改代码。
